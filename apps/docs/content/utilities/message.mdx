# Message Utilities

> Core utilities for converting, formatting, and manipulating chat messages across different formats and APIs.

Message utilities are essential for working with chat messages in Clarity Chat. They handle conversion between the Vercel AI SDK format (CoreMessage) and Clarity's internal format (Message), format messages for API requests, and provide token-aware truncation.

## When to Use

- **Integrate with Vercel AI SDK** - Convert between CoreMessage and Message formats
- **Prepare messages for API requests** - Format messages for Claude, OpenAI, or custom APIs
- **Manage token budgets** - Truncate message history to fit within model limits
- **Extract message content** - Get plain text from messages with complex content
- **Create new messages** - Generate properly structured user, assistant, or system messages
- **Validate message structure** - Ensure messages have required fields before sending

## Quick Start

```typescript
import {
  convertCoreMessageToMessage,
  convertMessageToCoreMessage,
  formatMessagesForAPI,
  truncateMessagesToTokenLimit,
  createUserMessage,
} from '@clarity-chat/react/utils/message'

// Convert from Vercel AI SDK format to Clarity format
const clarityMessage = convertCoreMessageToMessage(coreMessage, 'chat-123')

// Convert back to Vercel AI SDK format
const coreMessage = convertMessageToCoreMessage(clarityMessage)

// Format messages for API request
const apiMessages = formatMessagesForAPI(coreMessages)

// Truncate to fit token budget
const truncated = truncateMessagesToTokenLimit(messages, 4000)

// Create a new user message
const userMsg = createUserMessage('Hello, assistant!')
```

## Core Functions

### convertCoreMessageToMessage()

**Purpose:** Convert Vercel AI SDK CoreMessage format to Clarity's internal Message format

**Usage:**
```typescript
convertCoreMessageToMessage(
  coreMessage: CoreMessage,
  chatId?: string
): Message
```

**Parameters:**
- `coreMessage` - CoreMessage from useChatEnhanced or Vercel AI SDK
- `chatId` - Chat ID to assign to the message (default: "default")

**Returns:** Message object compatible with ChatWindow and Clarity components

**Common Patterns:**

```typescript
// Basic conversion
import { convertCoreMessageToMessage } from '@clarity-chat/react/utils/message'

const coreMessage = {
  id: 'msg-1',
  role: 'user',
  content: 'Hello!'
}
const message = convertCoreMessageToMessage(coreMessage, 'chat-123')
// Result: Full Message with status, timestamps, metadata

// Convert messages from useChatEnhanced hook
function ChatComponent() {
  const { messages } = useChatEnhanced()

  // Convert all messages for use with ChatWindow
  const clarityMessages = messages.map(msg =>
    convertCoreMessageToMessage(msg, chatId)
  )

  return <ChatWindow messages={clarityMessages} />
}

// Handle multimodal content
const coreMessage = {
  id: 'msg-2',
  role: 'user',
  content: [
    { type: 'text', text: 'What is this?' },
    { type: 'image', image: imageUrl }
  ]
}
const message = convertCoreMessageToMessage(coreMessage, 'chat-456')
// Extracts text content: "What is this?"

// Preserve tool invocations
const assistantMsg = {
  id: 'msg-3',
  role: 'assistant',
  content: 'Let me check that...',
  toolInvocations: [{
    toolCallId: 'call-1',
    toolName: 'searchDatabase',
    args: { query: 'user data' },
    state: 'result',
    result: { found: true }
  }]
}
const converted = convertCoreMessageToMessage(assistantMsg, 'chat-789')
// Tool invocations preserved in metadata
```

**Best Practices:**
- Always provide chatId for proper message organization
- Use batch conversion functions for arrays (convertCoreMessagesToMessages)
- Tool invocations are automatically preserved in metadata
- Function and tool roles are mapped to 'assistant'
- Generated timestamps use current time if not provided

### convertMessageToCoreMessage()

**Purpose:** Convert Clarity Message format back to Vercel AI SDK CoreMessage format

**Usage:**
```typescript
convertMessageToCoreMessage(message: Message): CoreMessage
```

**Parameters:**
- `message` - Clarity Message object

**Returns:** CoreMessage compatible with Vercel AI SDK and useChatEnhanced

**Common Patterns:**

```typescript
// Basic conversion back to CoreMessage
const clarityMessage: Message = {
  id: 'msg-1',
  chatId: 'chat-123',
  role: 'user',
  content: 'Hello!',
  status: 'sent',
  createdAt: new Date(),
  updatedAt: new Date()
}
const coreMessage = convertMessageToCoreMessage(clarityMessage)
// Result: { id: 'msg-1', role: 'user', content: 'Hello!' }

// Round-trip conversion
const original: CoreMessage = { id: '1', role: 'user', content: 'Hi' }
const clarity = convertCoreMessageToMessage(original, 'chat-1')
const back = convertMessageToCoreMessage(clarity)
// back ≈ original (non-essential fields stripped)

// Prepare messages for AI SDK hooks
function sendMessages(clarityMessages: Message[]) {
  const coreMessages = clarityMessages.map(convertMessageToCoreMessage)

  // Use with Vercel AI SDK
  await streamText({
    model: claude('claude-3-5-sonnet-20241022'),
    messages: coreMessages
  })
}

// Convert array of messages
import { convertMessagesToCoreMessages } from '@clarity-chat/react/utils/message'

const coreMessages = convertMessagesToCoreMessages(clarityMessages)
```

**Best Practices:**
- Conversion strips Clarity-specific fields (chatId, status, timestamps, metadata)
- Use for preparing messages to send to AI APIs
- Batch conversion available via convertMessagesToCoreMessages()
- Preserves essential fields: id, role, content
- Metadata and tool invocations are not preserved (use original CoreMessage if needed)

**See Also:** [convertCoreMessageToMessage()](#convertcoremessagetomessage), [formatMessagesForAPI()](#formatmessagesforapi)

### formatMessagesForAPI()

**Purpose:** Format CoreMessages for API requests, ensuring proper structure for different AI providers

**Usage:**
```typescript
formatMessagesForAPI(messages: CoreMessage[]): Array<{
  role: string
  content: string | Array<Record<string, any>>
  name?: string
  toolCallId?: string
}>
```

**Parameters:**
- `messages` - Array of CoreMessage objects

**Returns:** Array of API-ready message objects with proper structure

**Common Patterns:**

```typescript
// Format messages for API request
import { formatMessagesForAPI } from '@clarity-chat/react/utils/message'

const messages: CoreMessage[] = [
  { id: '1', role: 'system', content: 'You are helpful.' },
  { id: '2', role: 'user', content: 'Hello!' },
  { id: '3', role: 'assistant', content: 'Hi there!' }
]

const apiMessages = formatMessagesForAPI(messages)
// Ready to send to Claude, OpenAI, etc.

await fetch('/api/chat', {
  method: 'POST',
  body: JSON.stringify({ messages: apiMessages })
})

// Handle multimodal content
const multimodalMessages: CoreMessage[] = [{
  id: 'msg-1',
  role: 'user',
  content: [
    { type: 'text', text: 'Analyze this image:' },
    { type: 'image', image: base64Image }
  ]
}]

const formatted = formatMessagesForAPI(multimodalMessages)
// Properly structures image content for API

// Preserve tool information
const toolMessages: CoreMessage[] = [{
  id: 'msg-2',
  role: 'assistant',
  content: [
    {
      type: 'tool-call',
      toolCallId: 'call-1',
      toolName: 'search',
      args: { query: 'typescript' }
    }
  ]
}]

const apiReady = formatMessagesForAPI(toolMessages)
// Tool calls properly formatted for API

// Complete chat flow
async function sendChatRequest(messages: CoreMessage[]) {
  const formatted = formatMessagesForAPI(messages)

  const response = await fetch('/api/chat', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      messages: formatted,
      model: 'claude-3-5-sonnet-20241022',
      max_tokens: 1000
    })
  })

  return response.json()
}
```

**Best Practices:**
- Always format messages before sending to AI APIs
- Handles text, image, tool-call, and tool-result content types
- Preserves optional fields (name, toolCallId) when present
- String content remains string, array content remains array
- Use with both Clarity and Vercel AI SDK message formats

**See Also:** [convertMessageToCoreMessage()](#convertmessagetoco remessage), [truncateMessagesToTokenLimit()](#truncatemessagestotokenlimit)

### truncateMessagesToTokenLimit()

**Purpose:** Truncate message history to fit within model token limits, keeping most recent messages

**Usage:**
```typescript
truncateMessagesToTokenLimit(
  messages: CoreMessage[],
  maxTokens: number
): CoreMessage[]
```

**Parameters:**
- `messages` - Array of CoreMessage objects
- `maxTokens` - Maximum tokens to allow in result

**Returns:** Truncated array containing most recent messages that fit within limit

**Common Patterns:**

```typescript
// Truncate to fit model context
import { truncateMessagesToTokenLimit } from '@clarity-chat/react/utils/message'

const longHistory: CoreMessage[] = [...] // 100 messages
const truncated = truncateMessagesToTokenLimit(longHistory, 4000)
// Returns most recent messages totaling ~4000 tokens

// Manage context window
const MODEL_CONTEXT_WINDOW = 8192
const RESERVED_FOR_RESPONSE = 1000
const RESERVED_FOR_SYSTEM = 500
const maxHistoryTokens = MODEL_CONTEXT_WINDOW - RESERVED_FOR_RESPONSE - RESERVED_FOR_SYSTEM

const messagesForAPI = truncateMessagesToTokenLimit(messages, maxHistoryTokens)

// Preserve system message while truncating history
function prepareMessages(
  systemPrompt: string,
  messages: CoreMessage[],
  maxTokens: number
): CoreMessage[] {
  const systemMessage = createSystemMessage(systemPrompt)
  const systemTokens = estimateTokenCount(systemMessage)

  // Truncate user messages to fit remaining budget
  const truncatedMessages = truncateMessagesToTokenLimit(
    messages,
    maxTokens - systemTokens
  )

  return [systemMessage, ...truncatedMessages]
}

// Handle with error recovery
function safeTruncate(
  messages: CoreMessage[],
  maxTokens: number,
  minMessages: number = 1
): CoreMessage[] {
  const truncated = truncateMessagesToTokenLimit(messages, maxTokens)

  // Ensure at least minMessages are included
  if (truncated.length < minMessages) {
    return messages.slice(-minMessages)
  }

  return truncated
}

// Monitor truncation
const originalCount = messages.length
const truncated = truncateMessagesToTokenLimit(messages, 4000)
const truncatedCount = truncated.length

if (truncatedCount < originalCount) {
  console.log(`Truncated ${originalCount - truncatedCount} messages to fit token budget`)
}
```

**Best Practices:**
- Always truncate before sending to APIs with context limits
- Keeps most recent messages (truncates from beginning)
- Account for system prompts and reserved output tokens
- Use estimateTokenCount() for individual message estimation
- Consider minimum message requirements (at least 1 user message)
- Monitor truncation in logs/analytics to adjust limits

**See Also:** [estimateTokenCount()](#estimatetokencount), [Token Management Utilities](/utilities/token)

## Best Practices

### Format Conversion
- Use convertCoreMessageToMessage for SDK → Clarity conversion
- Use convertMessageToCoreMessage for Clarity → SDK conversion
- Batch convert arrays with convertCoreMessagesToMessages / convertMessagesToCoreMessages
- Always provide chatId when converting to Clarity format

### API Integration
- Always use formatMessagesForAPI before sending to AI APIs
- Truncate messages to fit context windows
- Reserve tokens for system prompts and response generation
- Validate messages before sending

### Token Management
- Use truncateMessagesToTokenLimit for long conversations
- Monitor truncation frequency to adjust limits
- Account for all token sources: system prompt, history, tools, response
- Use estimateTokens for approximate counts (see [Token Utilities](/utilities/token))

### Message Creation
- Use creation utilities (createUserMessage, etc.) for consistent IDs
- Auto-generated IDs prevent collisions even at same millisecond
- Provide custom IDs only when needed (e.g., persistence, deduplication)
- System messages should be added at conversation start

### Error Handling
- Validate messages before API calls
- Handle truncation gracefully (log when messages are dropped)
- Provide fallbacks for empty content
- Type check message content before processing

## Real-World Examples

### Chat Component with Format Conversion

```typescript
import {
  convertCoreMessageToMessage,
  truncateMessagesToTokenLimit,
  formatMessagesForAPI,
} from '@clarity-chat/react/utils/message'
import { useChatEnhanced } from '@clarity-chat/react/hooks'

function ChatComponent() {
  const { messages, sendMessage } = useChatEnhanced()
  const chatId = 'chat-123'

  // Convert for display in ChatWindow
  const clarityMessages = messages.map(msg =>
    convertCoreMessageToMessage(msg, chatId)
  )

  const handleSend = async (content: string) => {
    // Truncate to fit model context
    const truncated = truncateMessagesToTokenLimit(messages, 4000)

    // Format for API
    const apiMessages = formatMessagesForAPI(truncated)

    await sendMessage(content, { messages: apiMessages })
  }

  return <ChatWindow messages={clarityMessages} onSend={handleSend} />
}
```

### Custom API Integration

```typescript
import {
  createUserMessage,
  createSystemMessage,
  formatMessagesForAPI,
  truncateMessagesToTokenLimit,
  estimateTokenCount,
} from '@clarity-chat/react/utils/message'

async function sendToCustomAPI(
  userInput: string,
  history: CoreMessage[],
  systemPrompt: string
) {
  // Create messages
  const systemMsg = createSystemMessage(systemPrompt)
  const userMsg = createUserMessage(userInput)

  // Calculate token budget
  const systemTokens = estimateTokenCount(systemMsg)
  const userTokens = estimateTokenCount(userMsg)
  const maxHistoryTokens = 4000 - systemTokens - userTokens - 500 // 500 for response

  // Truncate history
  const truncatedHistory = truncateMessagesToTokenLimit(history, maxHistoryTokens)

  // Prepare final messages
  const allMessages = [systemMsg, ...truncatedHistory, userMsg]
  const apiMessages = formatMessagesForAPI(allMessages)

  // Send to API
  const response = await fetch('/api/custom-ai', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      messages: apiMessages,
      max_tokens: 500
    })
  })

  return response.json()
}
```

### Message Validation Pipeline

```typescript
import {
  validateMessage,
  hasToolCalls,
  extractToolCalls,
  messageToText,
} from '@clarity-chat/react/utils/message'

function processMessage(message: CoreMessage) {
  // Validate structure
  const validation = validateMessage(message)
  if (!validation.valid) {
    throw new Error(`Invalid message: ${validation.errors.join(', ')}`)
  }

  // Extract content
  const text = messageToText(message)
  console.log('Message text:', text)

  // Handle tool calls
  if (hasToolCalls(message)) {
    const toolCalls = extractToolCalls(message)
    console.log('Tool calls:', toolCalls)

    // Process each tool call
    for (const tool of toolCalls) {
      await executeTool(tool.toolName, tool.args)
    }
  }

  return message
}
```
