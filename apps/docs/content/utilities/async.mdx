# Async Utilities

> Production-ready async patterns for debouncing, throttling, retrying, timeout handling, and concurrency control.

Async utilities provide robust, well-tested implementations of common asynchronous patterns. They handle edge cases, provide proper cleanup, and integrate seamlessly with TypeScript for type-safe async operations.

## When to Use

- **Debounce user input** - Search boxes, form validation, autosave
- **Throttle high-frequency events** - Scroll, resize, mouse move handlers
- **Retry failed operations** - Network requests, external API calls
- **Add timeouts** - Prevent hanging requests, limit operation duration
- **Control concurrency** - Batch process with max concurrent operations
- **Wait for conditions** - Poll until resource is ready

## Quick Start

```typescript
import {
  debounce,
  throttle,
  retry,
  timeout,
  pool,
  sleep,
} from '@clarity-chat/utils/async'

// Debounce search input
const debouncedSearch = debounce(handleSearch, 300)
input.addEventListener('input', (e) => debouncedSearch(e.target.value))

// Throttle scroll handler
const throttledScroll = throttle(updateScrollPosition, 100)
window.addEventListener('scroll', throttledScroll)

// Retry failed API call
const data = await retry(() => fetch('/api/data'), { retries: 3 })

// Add timeout to request
const result = await timeout(longRunningRequest(), 5000)

// Process with concurrency limit
const results = await pool(
  urls.map(url => () => fetch(url)),
  3 // Max 3 concurrent requests
)

// Wait between operations
await sleep(1000)
```

## Core Functions

### debounce()

**Purpose:** Delay function execution until after a pause in calls

**Usage:**
```typescript
debounce<T>(
  fn: T,
  wait: number
): T & { cancel: () => void; flush: () => void }
```

**Parameters:**
- `fn` - Function to debounce
- `wait` - Milliseconds to wait after last call

**Returns:** Debounced function with `cancel()` and `flush()` methods

**Common Patterns:**

```typescript
// Search as user types
const debouncedSearch = debounce(async (query: string) => {
  const results = await searchAPI(query)
  setResults(results)
}, 300)

input.addEventListener('input', (e) => {
  debouncedSearch(e.target.value)
})

// React example
function SearchInput() {
  const [query, setQuery] = useState('')

  const debouncedSearch = useMemo(
    () => debounce((q: string) => performSearch(q), 300),
    []
  )

  const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    const value = e.target.value
    setQuery(value)
    debouncedSearch(value)
  }

  useEffect(() => {
    return () => debouncedSearch.cancel()
  }, [])

  return <input value={query} onChange={handleChange} />
}

// Autosave
const debouncedSave = debounce(async (data: FormData) => {
  await saveToServer(data)
  showToast('Saved!')
}, 2000)

// Call on every change
form.addEventListener('change', () => {
  debouncedSave(getFormData())
})

// Save immediately on unmount
window.addEventListener('beforeunload', () => {
  debouncedSave.flush() // Execute immediately
})

// Cancel pending save
cancelButton.addEventListener('click', () => {
  debouncedSave.cancel()
})

// Form validation
const debouncedValidate = debounce((email: string) => {
  if (validateEmail(email)) {
    setError(null)
  } else {
    setError('Invalid email')
  }
}, 500)

emailInput.addEventListener('input', (e) => {
  debouncedValidate(e.target.value)
})
```

**Best Practices:**
- Use 300ms for search inputs (balances responsiveness and API calls)
- Use 500-1000ms for autosave (longer for expensive operations)
- Always call `cancel()` on component unmount to prevent memory leaks
- Use `flush()` when you need immediate execution (e.g., before navigation)
- Memoize in React with `useMemo` to avoid recreating on every render

**See Also:** [throttle()](#throttle)

### throttle()

**Purpose:** Limit function execution to once per time period

**Usage:**
```typescript
throttle<T>(
  fn: T,
  wait: number,
  options?: { leading?: boolean; trailing?: boolean }
): T & { cancel: () => void }
```

**Parameters:**
- `fn` - Function to throttle
- `wait` - Minimum milliseconds between invocations
- `options` - Configure leading/trailing edge invocation
  - `leading` - Execute on first call (default: true)
  - `trailing` - Execute on last call (default: true)

**Returns:** Throttled function with `cancel()` method

**Common Patterns:**

```typescript
// Scroll handling
const throttledScroll = throttle((event: Event) => {
  const scrollTop = window.scrollY
  updateScrollPosition(scrollTop)
}, 100)

window.addEventListener('scroll', throttledScroll)

// Resize handling
const throttledResize = throttle(() => {
  const width = window.innerWidth
  updateLayout(width)
}, 200)

window.addEventListener('resize', throttledResize)

// Mouse move tracking
const throttledMouseMove = throttle((e: MouseEvent) => {
  updateCursorPosition(e.clientX, e.clientY)
}, 50, { leading: true, trailing: false })

canvas.addEventListener('mousemove', throttledMouseMove)

// API rate limiting
const throttledAPICall = throttle(async (data: RequestData) => {
  await sendToAPI(data)
}, 1000, { leading: true, trailing: true })

// Calls are spaced 1s apart
for (const item of items) {
  throttledAPICall(item)
}

// Infinite scroll
const throttledLoadMore = throttle(() => {
  if (isNearBottom()) {
    loadMoreItems()
  }
}, 300)

window.addEventListener('scroll', throttledLoadMore)

// Cleanup
window.addEventListener('beforeunload', () => {
  throttledScroll.cancel()
  throttledResize.cancel()
})
```

**Best Practices:**
- Use 16-50ms for animation frames (60fps = 16ms)
- Use 100-200ms for scroll/resize handlers
- Use 1000ms+ for API rate limiting
- Set `leading: true, trailing: false` for visual feedback (mouse move)
- Set `leading: false, trailing: true` for batching operations
- Always cancel on component unmount

**Debounce vs Throttle:**
- **Debounce** - Wait for pause (search, autosave, validation)
- **Throttle** - Limit frequency (scroll, resize, mouse move)

**See Also:** [debounce()](#debounce)

### retry()

**Purpose:** Retry failed async operations with exponential backoff

**Usage:**
```typescript
retry<T>(
  fn: () => Promise<T>,
  options?: {
    retries?: number           // Default: 3
    delay?: number             // Default: 1000ms
    backoffFactor?: number     // Default: 2
    maxDelay?: number          // Default: 30000ms
    shouldRetry?: (error: Error, attempt: number) => boolean
    onRetry?: (error: Error, attempt: number) => void
  }
): Promise<T>
```

**Parameters:**
- `fn` - Async function to retry
- `options` - Retry configuration

**Returns:** Result of successful invocation

**Throws:** Last error if all retries exhausted

**Common Patterns:**

```typescript
// Basic retry (3 attempts, exponential backoff: 1s, 2s, 4s)
const data = await retry(() => fetch('/api/data'))

// Custom retry config
const result = await retry(
  () => fetchUserData(userId),
  {
    retries: 5,
    delay: 500,
    backoffFactor: 1.5,
    maxDelay: 10000,
  }
)

// Conditional retry (only retry specific errors)
const response = await retry(
  async () => {
    const res = await fetch('/api/data')
    if (!res.ok) {
      const error = new Error(`HTTP ${res.status}`)
      ;(error as any).status = res.status
      throw error
    }
    return res.json()
  },
  {
    retries: 3,
    shouldRetry: (error, attempt) => {
      // Only retry 5xx errors and rate limits
      const status = (error as any).status
      return status >= 500 || status === 429
    },
    onRetry: (error, attempt) => {
      console.log(`Retry attempt ${attempt}: ${error.message}`)
    },
  }
)

// Database query retry
const user = await retry(
  () => db.users.findById(userId),
  {
    retries: 2,
    delay: 1000,
    shouldRetry: (error) => {
      // Retry connection errors, not validation errors
      return error.message.includes('connection')
    },
  }
)

// Streaming with retry
async function* streamWithRetry(url: string) {
  let attempt = 0
  while (attempt < 3) {
    try {
      const stream = await fetchStream(url)
      for await (const chunk of stream) {
        yield chunk
      }
      return
    } catch (error) {
      attempt++
      if (attempt >= 3) throw error
      await sleep(1000 * Math.pow(2, attempt))
    }
  }
}

// Combined with timeout
const data = await retry(
  () => timeout(fetchData(), 5000),
  { retries: 3 }
)
```

**Backoff Calculation:**
```typescript
// Attempt 1: delay = 1000ms
// Attempt 2: delay = 1000 * 2 = 2000ms
// Attempt 3: delay = 2000 * 2 = 4000ms
// Attempt 4: delay = 4000 * 2 = 8000ms (capped at maxDelay)
```

**Best Practices:**
- Retry transient failures (network, 5xx errors, timeouts)
- Don't retry permanent failures (validation, 4xx errors, auth)
- Use exponential backoff to avoid thundering herd
- Cap max retries at 3-5 for user-facing operations
- Use `shouldRetry` to avoid retrying non-retryable errors
- Log retry attempts for monitoring and debugging
- Combine with timeout to prevent hanging

**See Also:** [timeout()](#timeout), [UnifiedErrorHandler.retryWithBackoff()](/utilities/error-handling#unifiederrorhandlerretrywithbackoff)

### timeout()

**Purpose:** Add timeout to any promise

**Usage:**
```typescript
timeout<T>(
  promise: Promise<T>,
  ms: number,
  message?: string
): Promise<T>
```

**Parameters:**
- `promise` - Promise to wrap with timeout
- `ms` - Timeout in milliseconds
- `message` - Optional custom error message

**Returns:** Promise that rejects with TimeoutError if timeout reached

**Common Patterns:**

```typescript
// Basic timeout
try {
  const data = await timeout(fetchData(), 5000)
} catch (error) {
  if (error.name === 'TimeoutError') {
    console.log('Request timed out')
  }
}

// Fetch with timeout
const response = await timeout(
  fetch('/api/data'),
  3000,
  'API request timed out'
)

// Multiple timeouts
const [userData, postsData] = await Promise.all([
  timeout(fetchUser(), 2000),
  timeout(fetchPosts(), 5000),
])

// Retry with timeout
const data = await retry(
  () => timeout(fetchData(), 5000),
  { retries: 3 }
)

// AbortController alternative (native)
const controller = createAbortController(5000)
try {
  const response = await fetch(url, { signal: controller.signal })
} catch (error) {
  if (error.name === 'AbortError') {
    console.log('Request aborted')
  }
}

// Long-running operation
async function processWithProgress(items: Item[]) {
  for (const item of items) {
    try {
      await timeout(processItem(item), 10000)
    } catch (error) {
      if (error.name === 'TimeoutError') {
        console.warn(`Item ${item.id} processing timed out`)
        continue
      }
      throw error
    }
  }
}

// Timeout with cleanup
let cleanupFn: (() => void) | null = null

try {
  const result = await timeout(
    new Promise((resolve) => {
      const handle = startLongOperation()
      cleanupFn = () => cancelOperation(handle)
      handle.onComplete = resolve
    }),
    5000
  )
} catch (error) {
  if (error.name === 'TimeoutError') {
    cleanupFn?.()
  }
  throw error
}
```

**Best Practices:**
- Always handle TimeoutError specifically
- Set timeout based on expected operation duration + buffer
- Use shorter timeouts for user-facing operations (3-5s)
- Use longer timeouts for background operations (30-60s)
- Combine with retry for robust error handling
- Consider using AbortController for native fetch timeout
- Clean up resources when timeout occurs

**See Also:** [retry()](#retry), [createAbortController()](#createabortcontroller)

### pool()

**Purpose:** Execute async tasks with concurrency limit

**Usage:**
```typescript
pool<T>(
  tasks: Array<() => Promise<T>>,
  concurrency?: number // Default: 5
): Promise<T[]>
```

**Parameters:**
- `tasks` - Array of task functions (not promises!)
- `concurrency` - Maximum concurrent tasks

**Returns:** Array of results in original order

**Throws:** First error encountered (fail-fast)

**Common Patterns:**

```typescript
// Basic concurrent fetch
const urls = ['url1', 'url2', 'url3', 'url4', 'url5']
const results = await pool(
  urls.map(url => () => fetch(url).then(r => r.json())),
  3 // Max 3 concurrent requests
)

// File uploads
const files: File[] = [...]
const uploads = await pool(
  files.map(file => () => uploadFile(file)),
  2 // Upload 2 at a time
)

// Collect successes and failures (no fail-fast)
const results = await pool(
  urls.map(url => async () => {
    try {
      const data = await fetch(url).then(r => r.json())
      return { success: true as const, url, data }
    } catch (error) {
      return { success: false as const, url, error }
    }
  }),
  3
)

const successes = results.filter(r => r.success)
const failures = results.filter(r => !r.success)

console.log(`${successes.length} succeeded, ${failures.length} failed`)

// Process database records in batches
const userIds = [...]
const users = await pool(
  userIds.map(id => () => db.users.findById(id)),
  10 // 10 concurrent DB queries
)

// Image processing
const images = ['img1.jpg', 'img2.jpg', ...]
const processed = await pool(
  images.map(img => () => processImage(img)),
  4 // Use 4 CPU cores
)

// API pagination with concurrency
async function fetchAllPages(endpoint: string, totalPages: number) {
  const pageNumbers = Array.from({ length: totalPages }, (_, i) => i + 1)

  const pages = await pool(
    pageNumbers.map(page => () =>
      fetch(`${endpoint}?page=${page}`).then(r => r.json())
    ),
    5 // 5 concurrent page fetches
  )

  return pages.flatMap(page => page.items)
}

// With progress tracking
let completed = 0
const total = tasks.length

const results = await pool(
  tasks.map(task => async () => {
    const result = await task()
    completed++
    updateProgress(completed, total)
    return result
  }),
  3
)

// With retry
const results = await pool(
  urls.map(url => () => retry(() => fetch(url), { retries: 3 })),
  5
)
```

**Best Practices:**
- Set concurrency based on resource limits (network, CPU, memory)
- Use 3-5 for network requests (avoid overwhelming servers)
- Use CPU count for CPU-intensive tasks (e.g., image processing)
- Use 10-20 for database queries (depends on connection pool)
- Wrap tasks in try-catch to collect failures instead of fail-fast
- Always pass functions `() => promise`, not promises directly
- Monitor progress in long-running batch operations
- Combine with retry for robust batch processing

**Common Mistake:**
```typescript
// ❌ Wrong: passes promises (all start immediately)
await pool(urls.map(url => fetch(url)), 3)

// ✅ Correct: passes functions (start on demand)
await pool(urls.map(url => () => fetch(url)), 3)
```

**See Also:** [retry()](#retry), [timeout()](#timeout)

### sleep()

**Purpose:** Pause execution for specified duration

**Usage:**
```typescript
sleep(ms: number): Promise<void>
```

**Parameters:**
- `ms` - Milliseconds to sleep

**Returns:** Promise that resolves after duration

**Common Patterns:**

```typescript
// Simple delay
await sleep(1000) // Wait 1 second

// Rate limiting
for (const item of items) {
  await processItem(item)
  await sleep(100) // 100ms between items
}

// Polling
while (!condition()) {
  await sleep(500) // Check every 500ms
}

// Animation timing
async function animateSequence() {
  await showElement1()
  await sleep(300)
  await showElement2()
  await sleep(300)
  await showElement3()
}

// Retry with manual backoff
for (let attempt = 1; attempt <= 3; attempt++) {
  try {
    return await operation()
  } catch (error) {
    if (attempt < 3) {
      await sleep(1000 * attempt) // 1s, 2s
    }
  }
}

// Simulate slow network in development
async function fetchDataWithDelay() {
  const data = await fetchData()
  if (isDevelopment) {
    await sleep(2000) // Simulate slow network
  }
  return data
}
```

**Best Practices:**
- Use for manual timing control
- Prefer `waitUntil()` for condition-based waiting
- Prefer `retry()` for retry with automatic backoff
- Don't use sleep in production for polling (use `waitUntil` instead)

**See Also:** [waitUntil()](#waituntil), [retry()](#retry)

### waitUntil()

**Purpose:** Poll until condition becomes true

**Usage:**
```typescript
waitUntil(
  condition: () => boolean | Promise<boolean>,
  options?: {
    interval?: number  // Default: 100ms
    timeout?: number   // Default: 10000ms
  }
): Promise<void>
```

**Parameters:**
- `condition` - Function that returns boolean
- `options` - Polling configuration

**Returns:** Promise that resolves when condition is true

**Throws:** Error if timeout reached

**Common Patterns:**

```typescript
// Wait for DOM element
await waitUntil(
  () => document.querySelector('#loading') === null,
  { interval: 100, timeout: 5000 }
)

// Wait for resource load
await waitUntil(
  () => window.myLibrary !== undefined,
  { interval: 50, timeout: 3000 }
)

// Wait for async condition
await waitUntil(
  async () => {
    const status = await checkStatus()
    return status === 'ready'
  },
  { interval: 1000, timeout: 30000 }
)

// Wait for state change
await waitUntil(
  () => store.getState().isReady,
  { interval: 100 }
)

// Wait for connection
await waitUntil(
  async () => {
    try {
      await fetch('/health')
      return true
    } catch {
      return false
    }
  },
  { interval: 2000, timeout: 60000 }
)

// Test utilities
test('component loads data', async () => {
  render(<MyComponent />)

  await waitUntil(
    () => screen.queryByText('Loading...') === null,
    { timeout: 5000 }
  )

  expect(screen.getByText('Data loaded')).toBeInTheDocument()
})
```

**Best Practices:**
- Use for polling external resources (DOM, network, state)
- Set appropriate timeout based on expected wait time
- Use shorter interval for UI (50-100ms)
- Use longer interval for network checks (1000-2000ms)
- Handle timeout errors gracefully
- Prefer event-based waiting when possible (promises, observers)

**See Also:** [sleep()](#sleep)

### createAbortController()

**Purpose:** Create AbortController with automatic timeout

**Usage:**
```typescript
createAbortController(ms: number): AbortController
```

**Parameters:**
- `ms` - Timeout in milliseconds

**Returns:** AbortController that aborts after timeout

**Common Patterns:**

```typescript
// Fetch with timeout (native approach)
const controller = createAbortController(5000)

try {
  const response = await fetch(url, { signal: controller.signal })
  const data = await response.json()
} catch (error) {
  if (error.name === 'AbortError') {
    console.log('Request timed out or was cancelled')
  }
}

// Manual cancellation
const controller = createAbortController(30000)

fetchButton.addEventListener('click', async () => {
  try {
    const data = await fetch(url, { signal: controller.signal })
    updateUI(data)
  } catch (error) {
    if (error.name === 'AbortError') {
      console.log('Cancelled')
    }
  }
})

cancelButton.addEventListener('click', () => {
  controller.abort() // Cancel immediately
})

// React example
function DataFetcher() {
  useEffect(() => {
    const controller = createAbortController(5000)

    fetch('/api/data', { signal: controller.signal })
      .then(r => r.json())
      .then(setData)
      .catch(err => {
        if (err.name !== 'AbortError') {
          setError(err)
        }
      })

    return () => controller.abort() // Cleanup on unmount
  }, [])

  return <div>{data}</div>
}
```

**Best Practices:**
- Prefer AbortController for native fetch timeout
- Use with fetch API for cancellable requests
- Always check `error.name === 'AbortError'` to distinguish cancellation
- Cleanup AbortController on component unmount
- Timeout is automatically cleared on abort (no memory leaks)

**See Also:** [timeout()](#timeout)

## Best Practices

### Debounce vs Throttle

**Use Debounce When:**
- You want to wait for pause (search, autosave, validation)
- Last call is most important
- Multiple rapid calls should be collapsed to one

**Use Throttle When:**
- You want to limit frequency (scroll, resize, mouse move)
- All calls are important (sample at regular intervals)
- Visual feedback needs to be smooth

### Retry Strategy

**Retry These:**
- Network errors (ECONNREFUSED, ETIMEDOUT)
- 5xx server errors (temporary server issues)
- 429 rate limit errors
- Timeout errors

**Don't Retry These:**
- 4xx client errors (bad request, invalid data)
- 401/403 auth errors (need user action)
- Validation errors
- Logic errors

### Concurrency Control

**Low Concurrency (2-5):**
- External API calls (respect rate limits)
- File uploads (network bandwidth)
- Heavy CPU operations

**Medium Concurrency (5-10):**
- Database queries (connection pool limit)
- Internal API calls

**High Concurrency (10-20):**
- Lightweight operations
- Read-only operations
- Cached data fetching

### Timeout Values

**User-Facing Operations:**
- Search/autocomplete: 3-5s
- Form submission: 5-10s
- Page load: 10-15s

**Background Operations:**
- Batch processing: 30-60s
- Large file upload: 5-10 minutes
- Database migration: No timeout or very large

### Search with Debounce and Cancel

```typescript
import { debounce, timeout } from '@clarity-chat/utils/async'

function SearchComponent() {
  const [query, setQuery] = useState('')
  const [results, setResults] = useState([])
  const [loading, setLoading] = useState(false)
  const [controller, setController] = useState<AbortController | null>(null)

  const performSearch = useMemo(
    () => debounce(async (searchQuery: string) => {
      // Cancel previous request
      controller?.abort()

      if (!searchQuery) {
        setResults([])
        return
      }

      const newController = new AbortController()
      setController(newController)
      setLoading(true)

      try {
        // 5s timeout, cancellable
        const data = await timeout(
          fetch(`/api/search?q=${encodeURIComponent(searchQuery)}`, {
            signal: newController.signal,
          }).then(r => r.json()),
          5000
        )

        setResults(data.results)
      } catch (error) {
        if (error.name !== 'AbortError') {
          console.error('Search failed:', error)
        }
      } finally {
        setLoading(false)
      }
    }, 300),
    [controller]
  )

  useEffect(() => {
    return () => {
      performSearch.cancel()
      controller?.abort()
    }
  }, [])

  return (
    <div>
      <input
        value={query}
        onChange={(e) => {
          setQuery(e.target.value)
          performSearch(e.target.value)
        }}
        placeholder="Search..."
      />
      {loading && <Spinner />}
      <SearchResults results={results} />
    </div>
  )
}
```

### Batch Processing with Retry and Concurrency

```typescript
import { pool, retry, sleep } from '@clarity-chat/utils/async'

async function processBatch(items: Item[]) {
  console.log(`Processing ${items.length} items...`)

  let completed = 0
  let failed = 0

  const results = await pool(
    items.map(item => async () => {
      try {
        // Retry up to 3 times with exponential backoff
        const result = await retry(
          () => processItem(item),
          {
            retries: 3,
            delay: 1000,
            shouldRetry: (error) => {
              // Retry transient errors only
              return error.message.includes('ECONNREFUSED') ||
                     error.message.includes('timeout')
            },
            onRetry: (error, attempt) => {
              console.log(`Retry ${attempt} for item ${item.id}: ${error.message}`)
            },
          }
        )

        completed++
        updateProgress(completed, failed, items.length)

        return { success: true as const, item, result }
      } catch (error) {
        failed++
        updateProgress(completed, failed, items.length)

        return {
          success: false as const,
          item,
          error: error instanceof Error ? error : new Error(String(error)),
        }
      }
    }),
    5 // 5 concurrent operations
  )

  const successes = results.filter(r => r.success)
  const failures = results.filter(r => !r.success)

  console.log(`Completed: ${successes.length}, Failed: ${failures.length}`)

  if (failures.length > 0) {
    console.error('Failed items:', failures.map(f => f.item.id))
  }

  return { successes, failures }
}
```

### Infinite Scroll with Throttle

```typescript
import { throttle } from '@clarity-chat/utils/async'

function InfiniteScrollList() {
  const [items, setItems] = useState<Item[]>([])
  const [page, setPage] = useState(1)
  const [loading, setLoading] = useState(false)
  const [hasMore, setHasMore] = useState(true)

  const loadMore = async () => {
    if (loading || !hasMore) return

    setLoading(true)
    try {
      const newItems = await fetch(`/api/items?page=${page}`).then(r => r.json())

      setItems(prev => [...prev, ...newItems])
      setPage(prev => prev + 1)
      setHasMore(newItems.length > 0)
    } catch (error) {
      console.error('Failed to load more:', error)
    } finally {
      setLoading(false)
    }
  }

  const handleScroll = useMemo(
    () => throttle(() => {
      const scrollTop = window.scrollY
      const scrollHeight = document.documentElement.scrollHeight
      const clientHeight = window.innerHeight

      // Load more when 80% scrolled
      if (scrollTop + clientHeight >= scrollHeight * 0.8) {
        loadMore()
      }
    }, 300),
    [page, loading, hasMore]
  )

  useEffect(() => {
    window.addEventListener('scroll', handleScroll)
    return () => {
      handleScroll.cancel()
      window.removeEventListener('scroll', handleScroll)
    }
  }, [handleScroll])

  return (
    <div>
      {items.map(item => <ItemCard key={item.id} item={item} />)}
      {loading && <LoadingSpinner />}
      {!hasMore && <div>No more items</div>}
    </div>
  )
}
```
