# Error Handling Utilities

> Robust error handling with automatic retry, severity classification, and comprehensive error reporting.

Error handling utilities provide a robust foundation for managing errors across your Clarity Chat application. They offer type-safe error classes, automatic retry with exponential backoff, severity-based logging, and detailed error analytics.

## When to Use

- **Handle API errors consistently** - Network failures, timeouts, rate limits
- **Implement retry logic** - Automatic retry with exponential backoff for transient failures
- **Classify error severity** - Route errors based on criticality (low, medium, high, critical)
- **Track error patterns** - Monitor error frequency, types, and trends
- **Provide user-friendly messages** - Convert technical errors to user-readable text
- **Recover from failures gracefully** - Detect retryable vs permanent errors

## Quick Start

```typescript
import { UnifiedErrorHandler } from '@clarity-chat/utils/error-handler'
import { ApiError, isNetworkError } from '@clarity-chat/error-handling'

// Handle an error with context
try {
  await sendMessage(content)
} catch (error) {
  const processed = UnifiedErrorHandler.handle(error, {
    userId: user.id,
    operation: 'send-message',
  })

  if (processed.isRetryable) {
    // Show retry UI
  } else {
    // Show error message
    showToast(processed.formattedMessage)
  }
}

// Retry with automatic backoff
const response = await UnifiedErrorHandler.retryWithBackoff(
  () => fetch('/api/chat'),
  { maxRetries: 3 }
)

// Check error type
if (isNetworkError(error)) {
  console.log('Network issue - check connectivity')
}
```

## Core Functions

### UnifiedErrorHandler.handle()

**Purpose:** Process and log errors with consistent formatting, severity classification, and context tracking

**Usage:**
```typescript
UnifiedErrorHandler.handle(
  error: unknown,
  context?: ErrorContext
): ProcessedError
```

**Parameters:**
- `error` - Any error value (Error object, string, unknown)
- `context` - Optional context with userId, operation, requestId, metadata

**Returns:** ProcessedError with severity, formatted message, and retryability info

**Common Patterns:**

```typescript
// Basic error handling
try {
  await riskyOperation()
} catch (error) {
  const processed = UnifiedErrorHandler.handle(error)
  console.log(processed.formattedMessage) // User-friendly message
  console.log(processed.severity) // 'low' | 'medium' | 'high' | 'critical'
}

// With rich context
try {
  await api.sendMessage(message)
} catch (error) {
  const processed = UnifiedErrorHandler.handle(error, {
    userId: currentUser.id,
    operation: 'send-message',
    requestId: generateRequestId(),
    metadata: {
      messageLength: message.content.length,
      chatId: message.chatId,
      retryAttempt: 0,
    },
  })

  // Error is logged with full context automatically
  // History is maintained automatically
}

// React error boundary integration
class ErrorBoundary extends React.Component {
  componentDidCatch(error: Error, errorInfo: React.ErrorInfo) {
    const processed = UnifiedErrorHandler.handle(error, {
      operation: 'react-render',
      metadata: {
        componentStack: errorInfo.componentStack,
      },
    })

    // Severity-based UI response
    if (processed.severity === 'critical') {
      this.setState({ showFallbackUI: true })
    }
  }
}

// API error handling with status code context
async function callAPI(endpoint: string) {
  try {
    const response = await fetch(endpoint)
    if (!response.ok) {
      throw new ApiError('Request failed', {
        statusCode: response.status,
        endpoint,
      })
    }
    return response.json()
  } catch (error) {
    const processed = UnifiedErrorHandler.handle(error, {
      operation: 'api-call',
      metadata: { endpoint },
    })

    // processed.severity automatically determined
    // - 401/403 → 'high' (auth errors)
    // - 500/503 → 'medium' (server errors, retryable)
    // - 400 → 'medium' (validation errors)
    // - Network errors → 'low' (transient)

    throw error
  }
}
```

**Best Practices:**
- Always provide operation context for debugging
- Include userId for user-specific error tracking
- Use metadata for operation-specific details
- Error automatically logged based on severity
- Error stored in history (last 1000 errors)
- Severity determines logging level (critical/high → error, medium → warn, low → info)

### UnifiedErrorHandler.retryWithBackoff()

**Purpose:** Automatically retry failed operations with exponential backoff for transient failures

**Usage:**
```typescript
UnifiedErrorHandler.retryWithBackoff<T>(
  operation: () => Promise<T>,
  options?: Partial<RetryConfig>
): Promise<T>
```

**Parameters:**
- `operation` - Async function to retry
- `options` - Optional retry configuration

**RetryConfig Options:**
- `maxRetries` - Maximum retry attempts (default: 3)
- `retryDelay` - Initial delay in ms (default: 1000)
- `backoffMultiplier` - Backoff multiplier (default: 2)
- `maxRetryDelay` - Maximum delay cap in ms (default: 30000)
- `retryableErrors` - Array of retryable error type names

**Returns:** Result of successful operation

**Throws:** Last error if all retries exhausted or error is not retryable

**Common Patterns:**

```typescript
// Basic retry with defaults (3 retries, 1s → 2s → 4s delays)
const response = await UnifiedErrorHandler.retryWithBackoff(
  () => fetch('/api/chat')
)

// Custom retry configuration
const data = await UnifiedErrorHandler.retryWithBackoff(
  async () => {
    const res = await fetch('/api/data')
    if (!res.ok) throw new Error(`HTTP ${res.status}`)
    return res.json()
  },
  {
    maxRetries: 5,
    retryDelay: 500, // Start with 500ms
    backoffMultiplier: 1.5, // Gentler backoff
    maxRetryDelay: 10000, // Cap at 10s
  }
)

// Retry database operations
const user = await UnifiedErrorHandler.retryWithBackoff(
  () => db.users.findById(userId),
  { maxRetries: 2 }
)

// With error handling
try {
  const result = await UnifiedErrorHandler.retryWithBackoff(
    () => unreliableOperation(),
    { maxRetries: 3 }
  )
  console.log('Operation succeeded:', result)
} catch (error) {
  // All retries exhausted or error not retryable
  console.error('Operation failed permanently:', error)
}

// Conditional retry based on error type
async function robustAPICall(endpoint: string) {
  try {
    return await UnifiedErrorHandler.retryWithBackoff(
      async () => {
        const res = await fetch(endpoint)
        if (res.status === 429) {
          // Rate limit - always retry
          throw new Error('RateLimitError')
        }
        if (res.status >= 500) {
          // Server error - retry
          throw new Error('ServiceUnavailableError')
        }
        if (!res.ok) {
          // Client error - don't retry
          throw new Error(`ClientError: ${res.status}`)
        }
        return res.json()
      },
      {
        maxRetries: 4,
        retryableErrors: ['RateLimitError', 'ServiceUnavailableError', 'NetworkError'],
      }
    )
  } catch (error) {
    console.error('API call failed after retries:', error)
    throw error
  }
}

// Backoff delay calculation:
// Attempt 1: retryDelay * (backoffMultiplier ^ 0) = 1000ms
// Attempt 2: retryDelay * (backoffMultiplier ^ 1) = 2000ms
// Attempt 3: retryDelay * (backoffMultiplier ^ 2) = 4000ms
// Attempt 4: retryDelay * (backoffMultiplier ^ 3) = 8000ms (capped at maxRetryDelay)
```

**Best Practices:**
- Use for network requests, database queries, external APIs
- Retryable errors: NetworkError, TimeoutError, RateLimitError, 5xx errors
- Non-retryable errors: ValidationError, AuthenticationError, 4xx errors
- Cap maxRetries at 5 to avoid infinite loops
- Use exponential backoff (multiplier 1.5-2) to avoid thundering herd
- Log retry attempts for monitoring
- Consider circuit breakers for repeated failures

**See Also:** [UnifiedErrorHandler.isRetryable()](#unifiederrorhandlerisretryable), [UnifiedErrorHandler.configureRetry()](#unifiederrorhandlerconfigureretry)

### UnifiedErrorHandler.isRetryable()

**Purpose:** Determine if an error should be retried automatically

**Usage:**
```typescript
UnifiedErrorHandler.isRetryable(error: Error): boolean
```

**Parameters:**
- `error` - Error to check

**Returns:** true if error is transient and retryable

**Retryable Error Types:**
- NetworkError, TimeoutError, ConnectionError
- ServiceUnavailableError, RateLimitError
- APINetworkError, APITimeoutError
- Errors matching patterns: 'network', 'timeout', 'connection', 'service unavailable', 'rate limit'
- System errors: ECONNREFUSED, ENOTFOUND, ETIMEDOUT

**Common Patterns:**

```typescript
// Check before manual retry
async function sendWithRetry(message: string) {
  try {
    return await sendMessage(message)
  } catch (error) {
    if (error instanceof Error && UnifiedErrorHandler.isRetryable(error)) {
      // Wait and retry
      await sleep(2000)
      return await sendMessage(message)
    }
    // Not retryable - show error to user
    throw error
  }
}

// Conditional UI based on retryability
catch (error) {
  if (error instanceof Error) {
    const isRetryable = UnifiedErrorHandler.isRetryable(error)

    setErrorState({
      message: UnifiedErrorHandler.formatForDisplay(error),
      showRetryButton: isRetryable,
    })
  }
}

// Custom retry logic
let attempt = 0
const maxAttempts = 3

while (attempt < maxAttempts) {
  try {
    return await operation()
  } catch (error) {
    attempt++

    if (error instanceof Error) {
      const canRetry = UnifiedErrorHandler.isRetryable(error)

      if (!canRetry || attempt >= maxAttempts) {
        throw error
      }

      console.log(`Retry attempt ${attempt}/${maxAttempts}`)
      await sleep(1000 * attempt) // Linear backoff
    } else {
      throw error
    }
  }
}
```

**Best Practices:**
- Check retryability before implementing manual retry
- Combine with user feedback (show "Retry" button only for retryable errors)
- Non-retryable errors should surface immediately to users
- Consider error context when determining retry strategy

**See Also:** [UnifiedErrorHandler.retryWithBackoff()](#unifiederrorhandlerretrywithbackoff)

if (isAuthError(error)) {

if (isRecoverableError(error)) {
  showRetryButton()

const statusCode = getErrorStatusCode(error) // number | undefined

const errorCode = getErrorCode(error) // string | undefined

## Best Practices

### Error Handling Strategy
- Use UnifiedErrorHandler.handle() for all errors
- Provide context (userId, operation) for better debugging
- Check isRetryable before retry logic
- Use type guards to handle specific error types
- Display formatted messages to users, not raw Error.message

### Retry Logic
- Use retryWithBackoff for network/API calls
- Don't retry validation or auth errors
- Cap maxRetries at 3-5 attempts
- Use exponential backoff (multiplier 1.5-2.0)
- Log retry attempts for monitoring

### Severity Classification
Errors are automatically classified:
- **Critical** - Out of memory, system failures → immediate attention
- **High** - Auth/permission errors → log and alert
- **Medium** - Validation, parsing errors → monitor
- **Low** - Network, timeout errors → informational

### Error Tracking
- Monitor error statistics regularly
- Create error reports for incidents
- Clear history periodically (UnifiedErrorHandler.clearHistory())
- Set up alerts for high-severity errors
- Track average severity trends

### User Experience
- Show user-friendly messages (formatForDisplay)
- Provide retry buttons for retryable errors
- Display partial content from streaming errors
- Guide users with solution suggestions
- Link to documentation for complex errors

## Real-World Examples

### API Call with Retry and Error Handling

```typescript
import { UnifiedErrorHandler } from '@clarity-chat/utils/error-handler'
import { ApiError, isNetworkError } from '@clarity-chat/error-handling'

async function sendChatMessage(content: string, userId: string) {
  try {
    const result = await UnifiedErrorHandler.retryWithBackoff(
      async () => {
        const res = await fetch('/api/chat', {
          method: 'POST',
          body: JSON.stringify({ content, userId }),
        })

        if (!res.ok) {
          throw new ApiError(`Request failed: ${res.statusText}`, {
            statusCode: res.status,
            endpoint: '/api/chat',
            method: 'POST',
          })
        }

        return res.json()
      },
      { maxRetries: 3, retryDelay: 1000 }
    )

    return result
  } catch (error) {
    const processed = UnifiedErrorHandler.handle(error, {
      userId,
      operation: 'send-chat-message',
      metadata: { contentLength: content.length },
    })

    // Provide user feedback based on error type
    if (isNetworkError(error)) {
      showToast('Check your internet connection', 'warning')
    } else if (processed.isRetryable) {
      showToast('Service temporarily unavailable. Try again.', 'error')
    } else {
      showToast(processed.formattedMessage, 'error')
    }

    throw error
  }
}
```
