# Logging Utilities

> Production-ready structured logging with namespaces, log levels, request tracking, and flexible output formats for development and production environments.

Logging utilities provide a unified logging system with namespace isolation, configurable log levels, request ID tracking for distributed tracing, and support for both human-readable pretty-printed output and machine-parseable JSON logs.

## When to Use

- **Application logging** - Track application events, errors, and debugging info
- **Module-specific logging** - Create namespaced loggers for each module
- **Request tracking** - Track requests across services with request IDs
- **Production logging** - JSON-formatted logs for log aggregation services
- **Development debugging** - Pretty-printed logs with timestamps and colors
- **Error reporting** - Structured error logging with stack traces

## Quick Start

```typescript
import { getLogger } from '@clarity-chat/utils/logger'

// Create namespaced logger
const logger = getLogger('api-client')

// Log different levels
logger.info('Making API request', { url: '/api/data' })
logger.success('Request completed successfully')
logger.warn('Rate limit approaching', { remaining: 10 })
logger.error(new Error('Request failed'))
logger.debug('Debug details', { headers: {...} })

// Configure globally
import { configureLogger, setGlobalLogLevel, LogLevel } from '@clarity-chat/utils/logger'

configureLogger({
  verbose: true,
  timestamps: true,
  jsonOutput: false,
})

setGlobalLogLevel(LogLevel.DEBUG)
```

## Core Functions

### getLogger()

**Purpose:** Create a namespaced logger instance with independent log level control

**Usage:**
```typescript
getLogger(
  namespace: string,
  level?: LogLevel
): Logger
```

**Parameters:**
- `namespace` - Logger namespace (shown in output)
- `level` - Initial log level (defaults to global level)

**Returns:** Logger instance with methods:
- `info(message, ...args)` - Log informational message
- `success(message, ...args)` - Log success message (INFO level)
- `warn(message, ...args)` - Log warning
- `error(message, ...args)` - Log error (accepts Error objects)
- `debug(message, ...args)` - Log debug information (only shown when DEBUG enabled)
- `setLevel(level)` - Change logger's log level
- `getLevel()` - Get current log level

**Common Patterns:**

```typescript
// Module-specific loggers
const apiLogger = getLogger('api-client')
const dbLogger = getLogger('database')
const cacheLogger = getLogger('cache')

apiLogger.info('Fetching user data')
dbLogger.debug('Query executed', { query: 'SELECT * FROM users' })
cacheLogger.warn('Cache miss', { key: 'user:123' })

// Function-level logging
function processData(data: Data) {
  const logger = getLogger('data-processor')

  logger.info('Processing started', { items: data.length })

  try {
    const result = transform(data)
    logger.success('Processing completed', { resultCount: result.length })
    return result
  } catch (error) {
    logger.error(error)
    throw error
  }
}

// Class-based logging
class UserService {
  private logger = getLogger('user-service')

  async getUser(id: string) {
    this.logger.debug('Fetching user', { id })

    try {
      const user = await db.users.findById(id)
      this.logger.info('User retrieved', { id, username: user.name })
      return user
    } catch (error) {
      this.logger.error('Failed to fetch user', { id, error })
      throw error
    }
  }
}

// Error logging with stack traces
try {
  await riskyOperation()
} catch (error) {
  if (error instanceof Error) {
    logger.error(error) // Automatically logs stack trace in verbose mode
  } else {
    logger.error('Operation failed', { error })
  }
}

// Structured data logging
logger.info('User logged in', {
  userId: user.id,
  username: user.name,
  ip: request.ip,
  userAgent: request.headers['user-agent'],
})

// Debug logging (only shown when DEBUG=true or verbose mode)
logger.debug('Cache state', {
  size: cache.size,
  hitRate: cache.stats.hitRate,
  entries: Array.from(cache.keys()),
})

// Per-logger log level
const verboseLogger = getLogger('detailed-module', LogLevel.DEBUG)
const quietLogger = getLogger('quiet-module', LogLevel.ERROR)

verboseLogger.debug('This will show') // Shows
quietLogger.debug('This will not show') // Hidden

// Dynamic log level adjustment
const logger = getLogger('dynamic')

logger.setLevel(LogLevel.ERROR) // Only errors now
logger.info('Not shown')
logger.error('Shown')

logger.setLevel(LogLevel.DEBUG) // Back to debug
logger.debug('Now shown')
```

**Log Levels:**
```typescript
enum LogLevel {
  DEBUG = 0,  // Verbose debugging (🔍)
  INFO = 1,   // Informational (ℹ)
  WARN = 2,   // Warnings (⚠)
  ERROR = 3,  // Errors (✗)
}
```

**Best Practices:**
- Use descriptive namespaces (`api-client`, `auth-service`, `data-processor`)
- Include context data as additional arguments
- Use `debug()` for verbose information not needed in production
- Use `error()` with Error objects to capture stack traces
- Create logger at module/class level, not per function

**See Also:** [configureLogger()](#configurelogger), [setGlobalLogLevel()](#setgloballoglevel)

### configureLogger()

**Purpose:** Configure global logger options for all logger instances

**Usage:**
```typescript
configureLogger(options: {
  verbose?: boolean      // Enable debug logs
  silent?: boolean       // Suppress all output
  timestamps?: boolean   // Show timestamps
  jsonOutput?: boolean   // Output as JSON
}): void
```

**Parameters:**
- `options` - Logger configuration options

**Common Patterns:**

```typescript
// Development mode (pretty-printed with timestamps)
configureLogger({
  verbose: true,
  timestamps: true,
  jsonOutput: false,
})

// Production mode (JSON logs for aggregation)
configureLogger({
  verbose: false,
  timestamps: false,
  jsonOutput: true,
})

// Silent mode (testing)
configureLogger({
  silent: true,
})

// Environment-based configuration
const isDevelopment = process.env.NODE_ENV === 'development'
const isProduction = process.env.NODE_ENV === 'production'

configureLogger({
  verbose: isDevelopment,
  timestamps: isDevelopment,
  jsonOutput: isProduction,
})

// Enable verbose from environment
configureLogger({
  verbose: process.env.DEBUG === 'true',
  timestamps: true,
})
```

**Output Formats:**

```typescript
// Pretty-printed (jsonOutput: false)
// [13:45:23] [api-client] ℹ Making request { url: '/api/data' }
// [13:45:24] [api-client] ✓ Request completed

// JSON output (jsonOutput: true)
// {"timestamp":"2024-01-21T13:45:23.123Z","level":1,"namespace":"api-client","message":"Making request","data":[{"url":"/api/data"}]}
```

**Best Practices:**
- Configure once at application startup
- Use environment variables to control settings
- Enable `jsonOutput` in production for log aggregation (Datadog, Splunk, etc.)
- Enable `timestamps` in development for debugging
- Use `verbose` mode during debugging, disable in production

**See Also:** [setGlobalLogLevel()](#setgloballoglevel)

### setGlobalLogLevel()

**Purpose:** Set minimum log level for all loggers

**Usage:**
```typescript
setGlobalLogLevel(level: LogLevel): void
```

**Parameters:**
- `level` - Minimum log level to display

**Common Patterns:**

```typescript
import { setGlobalLogLevel, LogLevel } from '@clarity-chat/utils/logger'

// Only show errors
setGlobalLogLevel(LogLevel.ERROR)

// Show warnings and errors
setGlobalLogLevel(LogLevel.WARN)

// Show everything including debug
setGlobalLogLevel(LogLevel.DEBUG)

// Environment-based level
const logLevel = {
  'development': LogLevel.DEBUG,
  'staging': LogLevel.INFO,
  'production': LogLevel.WARN,
}[process.env.NODE_ENV || 'development']

setGlobalLogLevel(logLevel)

// Dynamic adjustment (e.g., admin endpoint)
app.post('/api/admin/log-level', (req, res) => {
  const { level } = req.body
  setGlobalLogLevel(LogLevel[level as keyof typeof LogLevel])
  res.json({ success: true, level })
})
```

**Best Practices:**
- Set at application startup based on environment
- Use INFO for production (balance between visibility and noise)
- Use DEBUG for development
- Use ERROR for critical production systems

**See Also:** [configureLogger()](#configurelogger)

### Request Tracking

**Purpose:** Track requests across services with request IDs for distributed tracing

**Usage:**
```typescript
setRequestId(id: string | null): void
getRequestId(): string | null
```

**Common Patterns:**

```typescript
import { setRequestId, getLogger } from '@clarity-chat/utils/logger'
import { randomUUID } from 'crypto'

// Express middleware
app.use((req, res, next) => {
  const requestId = req.headers['x-request-id'] as string ||
                    randomUUID()

  setRequestId(requestId)
  res.setHeader('x-request-id', requestId)

  next()
})

// Request handling
app.get('/api/data', async (req, res) => {
  const logger = getLogger('api-handler')

  logger.info('Received request')
  // [13:45:23] [api-handler] [a1b2c3d4] ℹ Received request

  const data = await fetchData()
  logger.info('Data fetched', { count: data.length })
  // [13:45:24] [api-handler] [a1b2c3d4] ℹ Data fetched { count: 10 }

  res.json(data)
})

// Clear request ID after handling
app.use((req, res, next) => {
  res.on('finish', () => {
    setRequestId(null)
  })
  next()
})

// Service-to-service calls
async function callUpstreamService() {
  const requestId = getRequestId()
  const logger = getLogger('upstream-client')

  logger.debug('Calling upstream service', { requestId })

  const response = await fetch('https://api.example.com/data', {
    headers: {
      'x-request-id': requestId || 'unknown',
    },
  })

  return response.json()
}
```

**Best Practices:**
- Generate request ID at API gateway/entry point
- Propagate request ID to all services
- Include request ID in all logs
- Clear request ID after request completes
- Use UUIDs for globally unique request IDs

## Best Practices

### Log Level Guidelines

**DEBUG (🔍):**
- Detailed debugging information
- Variable values, intermediate states
- Only in development/debugging
```typescript
logger.debug('Cache lookup', { key, value })
logger.debug('Function called', { args })
```

**INFO (ℹ):**
- General informational messages
- Request/response logging
- State changes
```typescript
logger.info('User logged in', { userId })
logger.info('Processing batch', { count: items.length })
```

**WARN (⚠):**
- Potentially harmful situations
- Deprecated API usage
- Approaching limits
```typescript
logger.warn('Rate limit approaching', { remaining: 10 })
logger.warn('Large payload detected', { size: formatBytes(size) })
```

**ERROR (✗):**
- Error conditions
- Exceptions and failures
- Requires attention
```typescript
logger.error(new Error('Database connection failed'))
logger.error('Payment processing failed', { orderId, error })
```

### Structured Logging

```typescript
// ✅ Good: Structured data
logger.info('User action', {
  action: 'purchase',
  userId: user.id,
  productId: product.id,
  amount: 99.99,
  currency: 'USD',
})

// ❌ Bad: String concatenation
logger.info(`User ${user.id} purchased ${product.id} for $99.99`)
```

### Error Logging

```typescript
// ✅ Good: Pass Error object
try {
  await operation()
} catch (error) {
  logger.error(error) // Captures stack trace
}

// ✅ Good: Error with context
catch (error) {
  logger.error('Operation failed', {
    operation: 'fetchData',
    userId,
    error,
  })
}

// ❌ Bad: Convert to string
catch (error) {
  logger.error(error.toString()) // Loses stack trace
}
```

### Production Configuration

```typescript
// production.ts
import { configureLogger, setGlobalLogLevel, LogLevel } from '@clarity-chat/utils/logger'

// JSON logs for aggregation services
configureLogger({
  jsonOutput: true,
  verbose: false,
  timestamps: false, // Timestamp added by log aggregator
})

// Only INFO and above
setGlobalLogLevel(LogLevel.INFO)

// development.ts
configureLogger({
  jsonOutput: false,
  verbose: true,
  timestamps: true,
})

setGlobalLogLevel(LogLevel.DEBUG)
```

## Real-World Examples

### Express Application with Request Tracking

```typescript
import express from 'express'
import { randomUUID } from 'crypto'
import {
  getLogger,
  setRequestId,
  configureLogger,
} from '@clarity-chat/utils/logger'

const app = express()
const logger = getLogger('app')

// Configure logging based on environment
const isProd = process.env.NODE_ENV === 'production'
configureLogger({
  jsonOutput: isProd,
  timestamps: !isProd,
  verbose: !isProd,
})

// Request ID middleware
app.use((req, res, next) => {
  const requestId = (req.headers['x-request-id'] as string) || randomUUID()
  setRequestId(requestId)
  res.setHeader('x-request-id', requestId)

  const startTime = Date.now()
  const reqLogger = getLogger('http')

  reqLogger.info('Request received', {
    method: req.method,
    path: req.path,
    ip: req.ip,
  })

  res.on('finish', () => {
    const duration = Date.now() - startTime
    reqLogger.info('Request completed', {
      method: req.method,
      path: req.path,
      status: res.statusCode,
      duration: `${duration}ms`,
    })
    setRequestId(null)
  })

  next()
})

// Route handlers with logging
app.post('/api/users', async (req, res) => {
  const logger = getLogger('users-api')

  try {
    logger.debug('Creating user', { data: req.body })

    const user = await createUser(req.body)

    logger.info('User created', {
      userId: user.id,
      username: user.username,
    })

    res.json(user)
  } catch (error) {
    logger.error('User creation failed', { error })
    res.status(500).json({ error: 'Internal server error' })
  }
})

// Startup
async function start() {
  try {
    await connectDatabase()
    logger.success('Database connected')

    await connectRedis()
    logger.success('Redis connected')

    app.listen(3000, () => {
      logger.success('Server started on port 3000')
    })
  } catch (error) {
    logger.error('Startup failed', { error })
    process.exit(1)
  }
}

start()
```

```typescript
async function processQueue() {
  logger.info('Worker started')

  while (true) {
    try {
      const job = await queue.pop()

      if (!job) {
        logger.debug('Queue empty, waiting...')
        await sleep(1000)
        continue
      }

      logger.info('Processing job', {
        jobId: job.id,
        type: job.type,
      })

      const result = await processJob(job)

      logger.success('Job completed', {
        jobId: job.id,
        duration: result.duration,
        output: result.output,
      })
    } catch (error) {
      logger.error('Job processing failed', { error })
      await sleep(5000) // Back off on error
    }
  }
```
