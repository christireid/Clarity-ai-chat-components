## Installation Issues

### Issue 1: `pnpm: command not found`

**Error Code:** `COMMAND_NOT_FOUND`

**Symptoms:**
```bash
pnpm install
-bash: pnpm: command not found
```

**Root Cause:** pnpm package manager is not installed globally.

**Solution:**

<Steps>
1. Install pnpm globally using npm:
   ```bash
   npm install -g pnpm
   ```

2. Verify installation:
   ```bash
   pnpm --version
   ```

3. If using Homebrew (macOS):
   ```bash
   brew install pnpm
   ```

4. For other package managers:
   ```bash
   # Using Volta
   volta install pnpm

   # Using Corepack (Node 16.13+)
   corepack enable
   corepack prepare pnpm@latest --activate
   ```
</Steps>

**Prevention:** Add pnpm to your project's `engines` field in `package.json`:

```json
{
  "engines": {
    "pnpm": ">=8.0.0"
  },
  "packageManager": "pnpm@8.15.0"
}
```

### Issue 2: `ERESOLVE: unable to resolve dependency tree`

**Error Code:** `ERESOLVE`

**Symptoms:**
```bash
npm ERR! code ERESOLVE
npm ERR! ERESOLVE unable to resolve dependency tree
```

**Root Cause:** Conflicting dependency versions or corrupted package-lock.json.

**Solution:**

<Steps>
1. Clear npm cache and reinstall:
   ```bash
   rm -rf node_modules package-lock.json
   npm cache clean --force
   npm install
   ```

2. If using pnpm (recommended):
   ```bash
   rm -rf node_modules pnpm-lock.yaml
   pnpm install --force
   ```

3. For peer dependency conflicts:
   ```bash
   npm install --legacy-peer-deps
   ```

4. Check for conflicting React versions:
   ```bash
   npm ls react react-dom
   ```
</Steps>

**Debugging with React DevTools:**

```tsx
// Add this to your component to inspect dependencies
useEffect(() => {
  console.log('React version:', React.version)
  console.log('Dependencies:', Object.keys(require('./package.json').dependencies))
}, [])
```

### Issue 3: Missing peer dependencies

**Error Code:** `PEER_DEP_MISSING`

**Symptoms:**
```bash
npm WARN @clarity-chat/react@2.0.0 requires a peer of framer-motion@^12.23.25 but none is installed.
```

**Root Cause:** Required peer dependencies not installed.

**Solution:**

<Steps>
1. Check which peer dependencies are required:
   ```bash
   npm info @clarity-chat/react peerDependencies
   ```

2. Install required peers (all users):
   ```bash
   npm install react react-dom framer-motion lucide-react zod
   ```

3. Install optional peers (if using those features):
   ```bash
   # For document loaders
   npm install pdfjs-dist mammoth

   # For syntax highlighting
   npm install shiki prismjs react-markdown remark-gfm

   # For token counting
   npm install flowtoken

   # For diagrams
   npm install mermaid
   ```

4. Use the automated installer script:
   ```bash
   cd packages/react
   node scripts/install-peers.js
   ```
</Steps>

**Prevention:** Create a `.npmrc` file in your project:

```ini
# .npmrc
auto-install-peers=true
strict-peer-dependencies=false
```

## Build and TypeScript Errors

### Issue 4: Build fails with TypeScript errors

**Error Code:** `TS_BUILD_ERROR`

**Symptoms:**
```bash
error TS2307: Cannot find module '@clarity-chat/react' or its corresponding type declarations.
```

**Root Cause:** TypeScript version incompatibility or missing type declarations.

**Solution:**

<Steps>
1. Ensure TypeScript 5.0+ is installed:
   ```bash
   npm install typescript@latest --save-dev
   ```

2. Check your `tsconfig.json` has proper module resolution:
   ```json
   {
     "compilerOptions": {
       "moduleResolution": "bundler", // or "node16", "nodenext"
       "resolveJsonModule": true,
       "esModuleInterop": true,
       "strict": true
     }
   }
   ```

3. Clear TypeScript cache:
   ```bash
   rm -rf node_modules/.cache
   rm -rf dist
   pnpm build
   ```

4. Restart TypeScript server in VS Code:
   - Press `Cmd+Shift+P` (macOS) or `Ctrl+Shift+P` (Windows/Linux)
   - Type "TypeScript: Restart TS Server"
</Steps>

**Debugging in VS Code:**

1. Open VS Code output panel: `View` → `Output` → Select `TypeScript`
2. Check for module resolution logs
3. Verify `tsconfig.json` is being used correctly

### Issue 6: Type errors with message format

**Error Code:** `TS_TYPE_MISMATCH`

**Symptoms:**
```typescript
Type '{ role: string; content: string; }' is not assignable to type 'Message'.
```

**Root Cause:** Incorrect message type or missing required fields.

**Solution:**

<Steps>
1. Import correct types:
   ```tsx
   import type { Message, CoreMessage } from '@clarity-chat/types'
   ```

2. Use proper message format:
   ```tsx
   // ✅ Correct message format
   const message: Message = {
     id: 'msg-1',           // Required
     role: 'user',          // Required: 'user' | 'assistant' | 'system'
     content: 'Hello',      // Required
     createdAt: new Date(), // Optional but recommended
   }

   // For core messages (minimal format)
   const coreMessage: CoreMessage = {
     role: 'user',
     content: 'Hello'
   }
   ```

3. Handle optional fields:
   ```tsx
   interface Message {
     id: string
     role: 'user' | 'assistant' | 'system'
     content: string
     createdAt?: Date
     metadata?: Record<string, unknown>
     toolCalls?: ToolCall[]
   }
   ```
</Steps>

### Issue 7: Next.js "use client" directive missing

**Error Code:** `NEXT_CLIENT_COMPONENT`

**Symptoms:**
```bash
Error: You're importing a component that needs useState. It only works in a Client Component but none of its parents are marked with "use client"
```

**Root Cause:** Using client-side hooks in a Server Component without the directive.

**Solution:**

<Steps>
1. Add `'use client'` to the top of your component file:
   ```tsx
   // app/chat/page.tsx
   'use client'

   import { ClarityChatApp } from '@clarity-chat/react'
   import '@clarity-chat/react/styles.css'

   export default function ChatPage() {
     return <ClarityChatApp api="/api/chat" />
   }
   ```

2. Or create a separate client component:
   ```tsx
   // components/ChatClient.tsx
   'use client'

   import { ChatWindow } from '@clarity-chat/react'

   export function ChatClient() {
     return <ChatWindow />
   }
   ```

   ```tsx
   // app/chat/page.tsx (Server Component)
   import { ChatClient } from '@/components/ChatClient'

   export default function ChatPage() {
     return <ChatClient />
   }
   ```
</Steps>

## Runtime Errors

### Issue 8: "Failed to fetch" error

**Error Code:** `FETCH_FAILED`

**Symptoms:**
```javascript
TypeError: Failed to fetch
    at fetch (native)
```

**Root Cause:** API route not running, incorrect URL, or CORS misconfiguration.

**Solution:**

<Steps>
1. Verify API is running:
   ```bash
   curl -X POST http://localhost:3000/api/chat \
     -H "Content-Type: application/json" \
     -d '{"messages": []}'
   ```

2. Check API route configuration (Next.js):
   ```tsx
   // app/api/chat/route.ts
   export async function POST(req: Request) {
     try {
       const { messages } = await req.json()

       // Your logic here

       return new Response(stream, {
         headers: {
           'Content-Type': 'text/event-stream',
           'Cache-Control': 'no-cache',
           'Connection': 'keep-alive',
           'Access-Control-Allow-Origin': '*', // Add for CORS
         },
       })
     } catch (error) {
       console.error('API Error:', error)
       return new Response(
         JSON.stringify({ error: 'Internal server error' }),
         { status: 500 }
       )
     }
   }
   ```

3. Add CORS headers if using different domains:
   ```tsx
   export async function OPTIONS(req: Request) {
     return new Response(null, {
       status: 200,
       headers: {
         'Access-Control-Allow-Origin': '*',
         'Access-Control-Allow-Methods': 'POST, OPTIONS',
         'Access-Control-Allow-Headers': 'Content-Type',
       },
     })
   }
   ```

4. Test with absolute URL:
   ```tsx
   <ClarityChatApp
     api={process.env.NEXT_PUBLIC_API_URL || 'http://localhost:3000/api/chat'}
   />
   ```
</Steps>

**Debugging with Browser DevTools:**

1. Open Network tab (F12)
2. Filter by "Fetch/XHR"
3. Check request/response headers
4. Look for HTTP status codes (404, 500, etc.)

### Issue 9: Streaming not working

**Error Code:** `STREAM_FAILED`

**Symptoms:**
- Messages appear all at once instead of streaming
- No incremental updates during response

**Root Cause:** Incorrect content type or response buffering.

**Solution:**

<Steps>
1. Ensure correct headers:
   ```tsx
   return new Response(stream, {
     headers: {
       'Content-Type': 'text/event-stream',  // Critical for SSE
       'Cache-Control': 'no-cache',
       'Connection': 'keep-alive',
       'X-Accel-Buffering': 'no', // Disable nginx buffering
     },
   })
   ```

2. For Vercel deployment, add edge runtime:
   ```tsx
   // app/api/chat/route.ts
   export const runtime = 'edge' // Prevents buffering

   export async function POST(req: Request) {
     // Your streaming logic
   }
   ```

3. Test streaming locally:
   ```tsx
   // Test streaming with curl
   curl -N http://localhost:3000/api/chat \
     -H "Content-Type: application/json" \
     -d '{"messages": [{"role": "user", "content": "Hello"}]}'
   ```

4. Check for response compression:
   ```tsx
   // Disable compression for streaming routes in Next.js
   // next.config.js
   module.exports = {
     compress: false, // For streaming routes
   }
   ```
</Steps>

**Browser Console Debugging:**

```tsx
// Monitor streaming in component
const { messages, isLoading } = useClarityChat({
  api: '/api/chat',
  onResponse: (response) => {
    console.log('Response received:', response.status)
  },
  onFinish: (message) => {
    console.log('Streaming finished:', message)
  },
  onError: (error) => {
    console.error('Streaming error:', error)
  },
})
```

### Issue 12: Error boundaries not catching errors

**Error Code:** `ERROR_BOUNDARY_BYPASS`

**Symptoms:**
- Errors crash the entire app
- Error boundary fallback doesn't show

**Root Cause:** Error boundaries only catch errors in render phase, not in event handlers or async code.

**Solution:**

<Steps>
1. Wrap components with error boundary:
   ```tsx
   import { ErrorBoundary } from '@clarity-chat/error-handling'

   function App() {
     return (
       <ErrorBoundary
         fallback={(error, reset) => (
           <div>
             <h2>Something went wrong</h2>
             <p>{error.message}</p>
             <button onClick={reset}>Try again</button>
           </div>
         )}
       >
         <ChatWindow />
       </ErrorBoundary>
     )
   }
   ```

2. For async errors, use error state:
   ```tsx
   const [error, setError] = useState<Error | null>(null)

   const handleSend = async (content: string) => {
     try {
       await append({ role: 'user', content })
     } catch (err) {
       setError(err as Error)
     }
   }

   if (error) {
     return <ErrorDisplay error={error} onRetry={() => setError(null)} />
   }
   ```

3. Use the hook-based error handler:
   ```tsx
   import { useEnhancedErrorHandler } from '@clarity-chat/error-handling'

   function ChatComponent() {
     const { handleError, error, reset } = useEnhancedErrorHandler()

     const handleSend = async (content: string) => {
       try {
         await append({ role: 'user', content })
       } catch (err) {
         handleError(err)
       }
     }

     if (error) {
       return <ErrorFallback error={error} reset={reset} />
     }

     return <ChatWindow />
   }
   ```
</Steps>

## Component-Specific Issues

### Issue 13: AudioRecorder - Microphone permission denied

**Error Code:** `MIC_PERMISSION_DENIED`

**Symptoms:**
```javascript
NotAllowedError: Permission denied
```

**Root Cause:** User hasn't granted microphone access or browser blocks access.

**Solution:**

<Steps>
1. Check browser permissions:
   - **Chrome:** `chrome://settings/content/microphone`
   - **Firefox:** `about:preferences#privacy` → Permissions → Microphone
   - **Safari:** System Preferences → Security & Privacy → Microphone

2. **Must use HTTPS in production:**
   ```bash
   # ❌ HTTP (will fail in production)
   http://example.com

   # ✅ HTTPS (required)
   https://example.com

   # ✅ Localhost (works in development)
   http://localhost:3000
   ```

3. Handle permission errors gracefully:
   ```tsx
   import { AudioRecorder } from '@clarity-chat/react'

   function VoiceInput() {
     const [permissionError, setPermissionError] = useState<string | null>(null)

     return (
       <>
         <AudioRecorder
           onError={(error) => {
             if (error.name === 'NotAllowedError') {
               setPermissionError(
                 'Microphone access denied. Please allow microphone access in your browser settings.'
               )
             }
           }}
           onStop={(blob, url) => {
             console.log('Recording complete:', blob.size, 'bytes')
           }}
         />
         {permissionError && (
           <div className="error-message">
             {permissionError}
             <a href="/help/microphone-setup">Setup guide</a>
           </div>
         )}
       </>
     )
   }
   ```

4. Request permission explicitly:
   ```tsx
   const requestMicrophoneAccess = async () => {
     try {
       const stream = await navigator.mediaDevices.getUserMedia({ audio: true })
       stream.getTracks().forEach(track => track.stop()) // Release immediately
       return true
     } catch (error) {
       console.error('Microphone access denied:', error)
       return false
     }
   }

   // Call before showing AudioRecorder
   const hasPermission = await requestMicrophoneAccess()
   if (hasPermission) {
     setShowRecorder(true)
   }
   ```
</Steps>

**Browser Console Debugging:**

```javascript
// Test microphone access in console
navigator.mediaDevices.getUserMedia({ audio: true })
  .then(stream => {
    console.log('✅ Microphone works!', stream)
    stream.getTracks().forEach(track => track.stop())
  })
  .catch(err => console.error('❌ Microphone test failed:', err))
```

### Issue 14: AudioRecorder - MediaRecorder not supported

**Error Code:** `MEDIARECORDER_UNSUPPORTED`

**Symptoms:**
```javascript
ReferenceError: MediaRecorder is not defined
```

**Root Cause:** Browser doesn't support MediaRecorder API.

**Browser Support:**
- ✅ Chrome/Edge 88+
- ✅ Safari 14.1+
- ✅ Firefox 105+
- ❌ IE 11

**Solution:**

<Steps>
1. Check feature availability:
   ```tsx
   const isMediaRecorderSupported = typeof MediaRecorder !== 'undefined'
   const isWebAudioSupported =
     typeof AudioContext !== 'undefined' ||
     typeof (window as any).webkitAudioContext !== 'undefined'

   if (!isMediaRecorderSupported) {
     return (
       <div>
         Audio recording requires a modern browser.
         <a href="https://www.google.com/chrome/">Download Chrome</a>
       </div>
     )
   }
   ```

2. Provide fallback UI:
   ```tsx
   function VoiceInputWrapper() {
     const [supported, setSupported] = useState(true)

     useEffect(() => {
       setSupported(typeof MediaRecorder !== 'undefined')
     }, [])

     if (!supported) {
       return (
         <TextInput
           placeholder="Voice input not available. Type your message..."
         />
       )
     }

     return <AudioRecorder />
   }
   ```

3. Use polyfill for older browsers:
   ```bash
   npm install audio-recorder-polyfill
   ```

   ```tsx
   // Conditional polyfill
   if (typeof window !== 'undefined' && !window.MediaRecorder) {
     import('audio-recorder-polyfill').then(({ default: MediaRecorder }) => {
       window.MediaRecorder = MediaRecorder as any
     })
   }
   ```
</Steps>

### Issue 15: CommandPalette - Keyboard shortcuts not working

**Error Code:** `KEYBOARD_SHORTCUT_BLOCKED`

**Symptoms:**
- Pressing Cmd+K/Ctrl+K doesn't open palette
- Browser's search bar opens instead

**Root Cause:** Browser shortcuts taking precedence.

**Solution:**

<Steps>
1. Prevent default behavior:
   ```tsx
   import { useEffect, useState } from 'react'
   import { CommandPalette } from '@clarity-chat/react'

   function App() {
     const [open, setOpen] = useState(false)

     useEffect(() => {
       const handleKeyDown = (e: KeyboardEvent) => {
         // Cmd+K (Mac) or Ctrl+K (Windows/Linux)
         if ((e.metaKey || e.ctrlKey) && e.key === 'k') {
           e.preventDefault() // Prevent browser search
           setOpen(true)
         }
       }

       document.addEventListener('keydown', handleKeyDown)
       return () => document.removeEventListener('keydown', handleKeyDown)
     }, [])

     return (
       <CommandPalette
         open={open}
         onClose={() => setOpen(false)}
         items={commands}
       />
     )
   }
   ```

2. Use alternative shortcuts:
   ```tsx
   const SHORTCUTS = {
     primary: { key: 'k', meta: true },
     alternative: { key: 'p', meta: true, shift: true }, // Cmd+Shift+P
   }

   const handleKeyDown = (e: KeyboardEvent) => {
     if (
       (e.metaKey || e.ctrlKey) &&
       e.key === 'k' &&
       !e.shiftKey
     ) {
       e.preventDefault()
       setOpen(true)
     }
     // Alternative: Cmd+Shift+P
     if (
       (e.metaKey || e.ctrlKey) &&
       e.shiftKey &&
       e.key === 'P'
     ) {
       e.preventDefault()
       setOpen(true)
     }
   }
   ```

3. Document shortcuts for users:
   ```tsx
   <div className="help-text">
     <kbd>⌘</kbd> + <kbd>K</kbd> (Mac) or
     <kbd>Ctrl</kbd> + <kbd>K</kbd> (Windows/Linux)
     <br />
     Alternative: <kbd>⌘</kbd> + <kbd>Shift</kbd> + <kbd>P</kbd>
   </div>
   ```
</Steps>

### Issue 16: OKLCH colors not rendering

**Error Code:** `OKLCH_UNSUPPORTED`

**Symptoms:**
- Colors appear incorrect or fall back to default
- Browser console shows CSS warnings

**Root Cause:** OKLCH is a modern CSS color format with limited browser support.

**Browser Support:**
- ✅ Chrome 111+ (March 2023)
- ✅ Edge 111+
- ✅ Safari 15.4+ (March 2022)
- ✅ Firefox 113+ (May 2023)

**Solution:**

<Steps>
1. Check browser support:
   ```tsx
   const supportsOKLCH =
     typeof CSS !== 'undefined' &&
     CSS.supports &&
     CSS.supports('color', 'oklch(50% 0.2 180)')

   if (!supportsOKLCH) {
     console.warn('OKLCH not supported, using RGB fallback')
   }
   ```

2. Provide CSS fallbacks:
   ```css
   .component {
     /* RGB fallback for older browsers */
     background: rgb(98, 182, 228);
     /* OKLCH for modern browsers */
     background: oklch(75% 0.18 195);
   }
   ```

3. Use PostCSS plugin for automatic fallbacks:
   ```bash
   npm install @csstools/postcss-oklab-function
   ```

   ```javascript
   // postcss.config.js
   module.exports = {
     plugins: {
       '@csstools/postcss-oklab-function': {
         preserve: true, // Keep OKLCH, add RGB fallback
       },
     },
   }
   ```

4. Use utility functions:
   ```tsx
   import { toOklchString, parseOklch } from '@clarity-chat/react'

   const color = parseOklch('75% 0.18 195')
   const cssValue = toOklchString(color)
   // Output: "oklch(75% 0.18 195)"
   ```
</Steps>

### Issue 17: Component breaks in Safari

**Error Code:** `SAFARI_COMPATIBILITY`

**Common Issues:**
- Web Audio API requires user gesture
- Different MediaRecorder codec support
- CSS Grid quirks

**Solution:**

<Steps>

   ```tsx
   const [audioContext, setAudioContext] = useState<AudioContext | null>(null)

     }

     setAudioContext(ctx)
   }

   return (
     <button onClick={initAudioContext}>
       Enable Audio
     </button>
   )
   ```

2. **MediaRecorder - Use Safari-compatible formats:**
   ```tsx
   <AudioRecorder

     mimeType="audio/mp4" // Or use auto-detection
   />
   ```

3. **CSS Grid - Add `-webkit-` prefix:**
   ```css
   .grid-container {
     display: -webkit-grid;
     display: grid;
     -webkit-grid-template-columns: repeat(3, 1fr);
     grid-template-columns: repeat(3, 1fr);
   ```

</Steps>

## API and Streaming Issues

### Issue 22: OpenAI rate limit exceeded

**Error Code:** `RATE_LIMIT_EXCEEDED`

**Symptoms:**
```json
{
  "error": {
    "message": "Rate limit reached for requests",
    "type": "rate_limit_error"
  }
}
```

**Solution:**

<Steps>
1. Add retry logic:
   ```tsx
   const chat = useClarityChat({
     api: '/api/chat',
     retry: {
       maxRetries: 3,
       delayMs: 1000,
       backoff: 'exponential', // 1s, 2s, 4s
     },
   })
   ```

2. Implement rate limiting on your API:
   ```tsx
   // app/api/chat/route.ts
   import { Ratelimit } from '@upstash/ratelimit'
   import { Redis } from '@upstash/redis'

   const ratelimit = new Ratelimit({
     redis: Redis.fromEnv(),
     limiter: Ratelimit.slidingWindow(10, '1 m'), // 10 requests per minute
   })

   export async function POST(req: Request) {
     const ip = req.headers.get('x-forwarded-for') ?? 'anonymous'
     const { success, limit, reset, remaining } = await ratelimit.limit(ip)

     if (!success) {
       return new Response(
         JSON.stringify({
           error: 'Too many requests',
           limit,
           reset,
           remaining,
         }),
         { status: 429 }
       )
     }

     // Process request
   }
   ```

3. Show user-friendly error:
   ```tsx
   const { error } = useClarityChat({ api: '/api/chat' })

   if (error && error.status === 429) {
     return (
       <div className="rate-limit-message">
         Too many requests. Please wait a moment and try again.
       </div>
     )
   }
   ```
</Steps>

### Issue 23: Anthropic/Claude API errors

**Error Code:** `ANTHROPIC_API_ERROR`

**Common Errors:**
- `invalid_api_key`: API key format incorrect
- `model_not_found`: Using deprecated model name

**Solution:**

<Steps>
1. Verify API key format:
   ```bash
   # Anthropic keys start with "sk-ant-"
   ANTHROPIC_API_KEY=sk-ant-api03-...

   # Check .env.local
   cat .env.local | grep ANTHROPIC_API_KEY
   ```

2. Use correct model names:
   ```tsx
   // ✅ Correct (as of 2026)
   model: 'claude-3-5-sonnet-20240620'
   model: 'claude-3-opus-20240229'
   model: 'claude-3-haiku-20240307'

   // ❌ Incorrect (deprecated)
   model: 'claude-3-sonnet'
   model: 'claude-2.1'
   ```

3. Handle API errors:
   ```tsx
   // app/api/chat/route.ts
   import Anthropic from '@anthropic-ai/sdk'

   const client = new Anthropic({
     apiKey: process.env.ANTHROPIC_API_KEY,
   })

   export async function POST(req: Request) {
     try {
       const { messages } = await req.json()

       const stream = await client.messages.create({
         model: 'claude-3-5-sonnet-20240620',
         max_tokens: 1024,
         messages,
         stream: true,
       })

       // Return stream
     } catch (error) {
       if (error instanceof Anthropic.APIError) {
         console.error('Anthropic API Error:', error.status, error.message)
         return new Response(
           JSON.stringify({ error: error.message }),
           { status: error.status }
         )
       }
       throw error
     }
   }
   ```
</Steps>

## Security Issues

### Issue 24: API key exposed in browser

**Error Code:** `API_KEY_EXPOSURE`

**Symptoms:**
- API key visible in Network tab
- Direct calls to AI provider from client

**Root Cause:** Calling AI API directly from client-side code.

**Solution:**

<Steps>
1. **NEVER expose API keys in client code:**
   ```tsx
   // ❌ WRONG - API key visible in browser
   const response = await fetch('https://api.openai.com/v1/chat/completions', {
     headers: {
       Authorization: `Bearer ${process.env.NEXT_PUBLIC_OPENAI_API_KEY}` // EXPOSED!
     },
   })
   ```

2. **ALWAYS use server-side API routes:**
   ```tsx
   // ✅ CORRECT - Client calls your backend
   const response = await fetch('/api/chat', {
     method: 'POST',
     body: JSON.stringify({ messages }),
   })
   ```

3. **Keep API keys server-side only:**
   ```bash
   # .env.local (server-side only)
   OPENAI_API_KEY=sk-...           # ✅ Server-side
   ANTHROPIC_API_KEY=sk-ant-...    # ✅ Server-side

   # ❌ NEVER use NEXT_PUBLIC_ prefix for API keys
   # NEXT_PUBLIC_OPENAI_API_KEY=sk-... # ❌ EXPOSED to browser!
   ```

4. **Add to .gitignore:**
   ```bash
   # .gitignore
   .env.local
   .env.*.local
   .env.development.local
   .env.test.local
   .env.production.local
   ```
</Steps>

**Symptoms:**
- Unexpected high API costs
- Abuse from bad actors
- Service degradation

**Solution:**

<Steps>

   ```tsx
   // app/api/chat/route.ts
   import { Ratelimit } from '@upstash/ratelimit'
   import { Redis } from '@upstash/redis'

   const ratelimit = new Ratelimit({
     redis: Redis.fromEnv(),
     limiter: Ratelimit.slidingWindow(10, '1 m'), // 10 per minute
     analytics: true,
   })

   export async function POST(req: Request) {
     const identifier = req.headers.get('x-forwarded-for') ?? 'anonymous'

     const { success } = await ratelimit.limit(identifier)

     if (!success) {
       return new Response('Too many requests', { status: 429 })
     }

     // Process request
   }
   ```

   ```tsx
   import { getServerSession } from 'next-auth'

     const session = await getServerSession()

     }

     // Process authenticated request
   }
   ```

   ```tsx
   // Track API usage
   ```

   - Install [React DevTools](https://react.dev/learn/react-developer-tools)

   - Stop recording
   - Analyze flame graph for slow renders

3. **Find re-render causes:**
   - Enable "Highlight updates when components render"
   - Watch which components flash on updates
   - Optimize with `memo`, `useMemo`, `useCallback`

### Using Browser Console

1. **Monitor network requests:**
   ```javascript
   // In browser console
   performance.getEntriesByType('resource')
     .filter(r => r.name.includes('/api/'))
     .forEach(r => console.log(r.name, r.duration))
   ```

2. **Debug streaming:**
   ```javascript
   // Monitor SSE events
   const eventSource = new EventSource('/api/chat')
   eventSource.onmessage = (event) => {
     console.log('SSE event:', event.data)
   }
   ```

3. **Check memory usage:**
   ```javascript
   // Monitor heap size
   setInterval(() => {
     const { usedJSHeapSize, totalJSHeapSize } = performance.memory
     console.log(`Memory: ${(usedJSHeapSize / 1048576).toFixed(2)} MB / ${(totalJSHeapSize / 1048576).toFixed(2)} MB`)
   }, 5000)
   ```

### Using TypeScript

1. **Enable strict mode:**
   ```json
   // tsconfig.json
   {
     "compilerOptions": {
       "strict": true,
       "noImplicitAny": true,
       "strictNullChecks": true
     }
   }
   ```

2. **Add type guards:**
   ```tsx
   function isMessage(obj: unknown): obj is Message {
     return (
       typeof obj === 'object' &&
       obj !== null &&
       'role' in obj &&
       'content' in obj
     )
   }

   if (isMessage(data)) {
     // TypeScript knows data is Message

   }
   ```
