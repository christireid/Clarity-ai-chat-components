# Search Functionality

This directory contains the auto-generated search index for the documentation site.

## Overview

The search functionality uses [Fuse.js](https://fusejs.io/) for fuzzy search with a comprehensive index of all documentation pages.

### Files

- **`search-data.ts`** - Auto-generated search index with all documentation pages (241+ items)
- **`README.md`** - This file

## Search Index

The search index is auto-generated by scanning all `page.tsx` and `page.mdx` files in the `app/` directory and extracting:

- **Title** - From Next.js `metadata.title` export or `<h1>` tags
- **Description** - From Next.js `metadata.description` export
- **Type** - Inferred from file path:
  - `component` - Components from `/reference/components/`
  - `hook` - Hooks from `/reference/hooks/`
  - `example` - Examples from `/examples/`
  - `cookbook` - Recipes from `/cookbook/`
  - `concept` - Core concepts from `/learn/concepts/`
  - `deployment` - Deployment guides from `/learn/deployment/`
  - `integration` - Integrations from `/integrations/`
  - `guide` - Everything else (tutorials, guides, etc.)
- **Href** - Generated from file path (e.g., `app/learn/quick-start/page.tsx` → `/learn/quick-start`)
- **Category** - Top-level section (e.g., 'learn', 'reference', 'examples')

## Regenerating the Search Index

The search index must be regenerated whenever:

- New documentation pages are added
- Page titles or descriptions change
- Pages are moved or deleted

### Command

```bash
# From the docs directory
cd apps/docs
node scripts/generate-search-index.mjs
```

### When to Run

You should regenerate the search index:

1. **Before deployment** - Ensure all new content is searchable
2. **After major content updates** - Keep search results fresh
3. **When adding new pages** - Make them discoverable
4. **In CI/CD** (optional) - Automate index generation on builds

### Automated Generation (Optional)

To automatically regenerate the search index on every build, add this to your build script in `package.json`:

```json
{
  "scripts": {
    "prebuild": "node scripts/generate-search-index.mjs",
    "build": "next build"
  }
}
```

Or add to your CI/CD pipeline:

```yaml
# .github/workflows/deploy.yml
- name: Generate search index
  run: |
    cd apps/docs
    node scripts/generate-search-index.mjs

- name: Build docs
  run: npm run build
```

## Search UI

The search interface is implemented in:

**`components/Navigation/SearchDialog.tsx`**

### Features

- **Fuzzy search** with Fuse.js (0.3 threshold)
- **Keyboard navigation** (↑↓ arrows, Enter to select, Esc to close)
- **Type filtering** with colored badges
- **Icon indicators** for different content types
- **Real-time results** as you type
- **Empty state** when no results found
- **Accessible** with ARIA attributes

### Keyboard Shortcuts

- **Cmd+K** (Mac) / **Ctrl+K** (Windows/Linux) - Open search
- **↑↓** - Navigate results
- **Enter** - Go to selected page
- **Esc** - Close search dialog

### Search Configuration

Fuse.js search options (in `SearchDialog.tsx`):

```typescript
{
  keys: ['title', 'description', 'type'],
  threshold: 0.3,  // Lower = more strict, higher = more fuzzy
  includeScore: true,
}
```

**Threshold guide**:
- `0.0` = Perfect match only
- `0.3` = Somewhat fuzzy (current)
- `0.5` = Very fuzzy
- `1.0` = Matches everything

## Customization

### Adding Custom Search Fields

To add custom search fields, modify both:

1. **Generation script** (`scripts/generate-search-index.mjs`):
   ```javascript
   searchItems.push({
     title: metadata.title,
     description: metadata.description,
     tags: metadata.tags, // NEW: Add tags
     // ...
   })
   ```

2. **Search interface** (`search-data.ts`):
   ```typescript
   export interface SearchItem {
     // ...
     tags?: string[]  // NEW: Add to type
   }
   ```

3. **Fuse.js keys** (`SearchDialog.tsx`):
   ```typescript
   keys: ['title', 'description', 'type', 'tags'], // Include new field
   ```

### Styling Search Results

Search result styling is in `SearchDialog.tsx`:

- **Icons** - `getTypeIcon()` function
- **Badge colors** - `getTypeBadge()` function
- **Result layout** - JSX in the render function

### Performance

The search index is loaded on demand when the search dialog is opened. With 241 items, the index size is approximately:

- **Uncompressed**: ~40KB
- **Gzipped**: ~8KB

This has minimal impact on page load performance as it's code-split and only loaded when needed.

## Troubleshooting

### Search shows no results

1. Check if search data is generated: `cat lib/search-data.ts | head -20`
2. Verify import path in `SearchDialog.tsx`: `@/lib/search-data`
3. Check for TypeScript errors: `npm run typecheck`

### Some pages are missing from search

Pages are skipped if they don't have a `title` in their metadata. Add:

```tsx
export const metadata: Metadata = {
  title: 'Page Title',
  description: 'Page description',
}
```

### Search is slow

With 241 items, search should be instant. If it's slow:

1. Lower Fuse.js threshold for faster matching
2. Reduce `keys` array to only essential fields
3. Check for memory leaks or re-renders

### Icons are missing

Make sure all icon imports are in `SearchDialog.tsx`:

```tsx
import { Search, Hash, FileText, Book, Wrench, Code2, Sparkles } from 'lucide-react'
```
