  # Accessibility Guide
  
  <p className="sb-lead">
    Building inclusive experiences that work for everyone, regardless of ability or assistive technology.
  </p>

  ## 🎯 Our Commitment

  Clarity Chat components are designed to be **WCAG 2.1 Level AA compliant**. Accessibility is not an afterthought—it's built into every component from the ground up.

  ## 🔍 Testing with Storybook

  ### a11y Addon

  Every story in this Storybook is automatically tested for accessibility issues using the **a11y addon**.

  **How to use it:**
  
  1. Open any story
  2. Look for the "Accessibility" tab at the bottom
  3. Review any violations, passes, or incomplete checks
  4. Fix violations before shipping

  **Common checks:**
  - Color contrast ratios
  - Form label associations
  - Button text content
  - Image alt attributes
  - Heading hierarchy
  - Landmark regions

  ## ⌨️ Keyboard Navigation

  All interactive components support full keyboard navigation.

  ### Standard Patterns

  | Key | Action |
  |-----|--------|
  | `Tab` | Move focus forward |
  | `Shift + Tab` | Move focus backward |
  | `Enter` | Activate button/link |
  | `Space` | Activate button, toggle checkbox |
  | `Escape` | Close dialog/menu |
  | `Arrow Keys` | Navigate lists, menus, tabs |
  | `Home` | Jump to first item |
  | `End` | Jump to last item |

  ### Component-Specific

  **Dropdown Menus:**
  - `↓` / `↑` - Navigate items
  - `Enter` - Select item
  - `Escape` - Close menu
  - Type to search items

  **Command Palette:**
  - `Cmd/Ctrl + K` - Open
  - `↓` / `↑` - Navigate results
  - `Enter` - Execute command
  - `Escape` - Close

  **Chat Input:**
  - `Enter` - Send message
  - `Shift + Enter` - New line
  - `Cmd/Ctrl + Enter` - Alternative send

  ## 🎨 Visual Design

  ### Color Contrast

  All text meets WCAG AA standards:
  - **Normal text**: 4.5:1 minimum contrast ratio
  - **Large text** (18px+ or 14px+ bold): 3:1 minimum
  - **UI components**: 3:1 minimum for interactive elements

  **Tools we use:**
  - WebAIM Contrast Checker
  - Chrome DevTools Color Contrast
  - Storybook a11y addon

  ### Focus Indicators

  All interactive elements have clear, visible focus indicators:

  ```css
  /* Example focus styles */
  .focusable:focus-visible {
    outline: 2px solid var(--color-primary);
    outline-offset: 2px;
  }
  ```

  **Never** remove focus styles with `outline: none` unless providing an alternative!

  ### Motion & Animation

  We respect the `prefers-reduced-motion` setting:

  ```css
  @media (prefers-reduced-motion: reduce) {
    * {
      animation-duration: 0.01ms !important;
      transition-duration: 0.01ms !important;
    }
  }
  ```

  ## 📱 Screen Reader Support

  ### Semantic HTML

  We use proper semantic HTML elements:

  ```tsx
  // ✅ Good: Semantic button
  <button onClick={handleClick}>Save</button>

  // ❌ Bad: Non-semantic clickable div
  <div onClick={handleClick}>Save</div>
  ```

  ### ARIA Attributes

  When semantic HTML isn't enough, we use ARIA:

  **Labels:**
  ```tsx
  <button aria-label="Close dialog">
    <XIcon />
  </button>
  ```

  **Descriptions:**
  ```tsx
  <input
    aria-describedby="password-hint"
  />
  <div id="password-hint">
    Must be at least 8 characters
  </div>
  ```

  **Live Regions:**
  ```tsx
  <div
    role="status"
    aria-live="polite"
    aria-atomic="true"
  >
    Message sent successfully
  </div>
  ```

  **Dynamic Content:**
  ```tsx
  <button
    aria-expanded={isOpen}
    aria-controls="menu-content"
  >
    Menu
  </button>
  ```

  ## 🧪 Testing Checklist

  Before shipping a component, verify:

  ### Keyboard Navigation
  - [ ] All interactive elements are focusable
  - [ ] Tab order is logical
  - [ ] Focus indicators are visible
  - [ ] Keyboard shortcuts work
  - [ ] No keyboard traps

  ### Screen Readers
  - [ ] All images have alt text
  - [ ] Buttons have accessible names
  - [ ] Form inputs have labels
  - [ ] Dynamic content announces properly
  - [ ] Error messages are associated with fields

  ### Visual
  - [ ] Text has sufficient contrast
  - [ ] Focus indicators are visible
  - [ ] UI works at 200% zoom
  - [ ] Color is not the only indicator
  - [ ] Animations respect prefers-reduced-motion

  ### Tools
  - [ ] Storybook a11y addon shows no violations
  - [ ] axe DevTools finds no issues
  - [ ] Lighthouse accessibility score is 90+
  - [ ] Manual screen reader testing passes

  ## 🛠️ Common Patterns

  ### Accessible Forms

  ```tsx
  <div className="space-y-2">
    <label htmlFor="email" className="text-sm font-medium">
      Email Address
    </label>
    <input
      id="email"
      type="email"
      aria-required="true"
      aria-invalid={hasError}
      aria-describedby={hasError ? "email-error" : undefined}
    />
    {hasError && (
      <p id="email-error" className="text-sm text-red-600" role="alert">
        Please enter a valid email address
      </p>
    )}
  </div>
  ```

  ### Accessible Modals

  ```tsx
  <Dialog
    open={open}
    onOpenChange={setOpen}
    role="dialog"
    aria-labelledby="dialog-title"
    aria-describedby="dialog-description"
  >
    <DialogContent>
      <DialogTitle id="dialog-title">
        Confirm Action
      </DialogTitle>
      <DialogDescription id="dialog-description">
        Are you sure you want to delete this item?
      </DialogDescription>
      {/* Focus trap active */}
      {/* Escape key closes */}
      {/* Focus returns to trigger on close */}
    </DialogContent>
  </Dialog>
  ```

  ### Accessible Loading States

  ```tsx
  <Button disabled={isLoading} aria-busy={isLoading}>
    {isLoading ? (
      <>
        <Spinner aria-hidden="true" />
        <span className="sr-only">Loading...</span>
        <span aria-hidden="true">Loading</span>
      </>
    ) : (
      'Submit'
    )}
  </Button>
  ```

  ### Accessible Icons

  ```tsx
  // Decorative icon (hidden from screen readers)
  <button>
    <TrashIcon aria-hidden="true" />
    Delete
  </button>

  // Icon-only button (needs label)
  <button aria-label="Delete item">
    <TrashIcon />
  </button>
  ```

  ## 🎓 Best Practices

  ### Do's ✅

  - Use semantic HTML elements
  - Provide text alternatives for images
  - Ensure sufficient color contrast
  - Support keyboard navigation
  - Test with actual assistive technologies
  - Write descriptive link text
  - Use proper heading hierarchy
  - Announce dynamic content changes
  - Provide skip links for navigation
  - Make forms accessible

  ### Don'ts ❌

  - Don't rely on color alone
  - Don't remove focus indicators
  - Don't use `div` for buttons
  - Don't auto-play audio/video
  - Don't use tiny click targets
  - Don't trap keyboard focus
  - Don't ignore ARIA errors
  - Don't assume everyone uses a mouse
  - Don't hide important content from screen readers
  - Don't forget alt text

  ## 🤝 Contributing

  When adding new components:

  1. Start with semantic HTML
  2. Add keyboard support
  3. Include ARIA when needed
  4. Test with a11y addon
  5. Verify with screen reader
  6. Check color contrast
  7. Document keyboard shortcuts
  8. Add to this guide if needed

  ## 💬 Questions?

  If you're unsure about an accessibility implementation:

  1. Check the ARIA Authoring Practices
  2. Look at similar components in this Storybook
  3. Test with the a11y addon
  4. Ask for help in code review

  **Remember**: Good accessibility often means good UX for everyone. Clear labels, logical tab order, and keyboard shortcuts benefit all users, not just those using assistive technology.
