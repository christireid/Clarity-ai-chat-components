## Performance Characteristics

⚡ **Optimized for Production**
- RAF batching prevents layout thrashing
- Connection ID tracking prevents concurrent stream corruption
- Proper reader cancellation eliminates memory leaks
- 60fps rendering during streaming

📊 **Measured Performance:**
- Smooth rendering up to 200 tokens/sec
- Less than 10 forced synchronous layouts per update
- Consistent 60fps scrolling
- Memory-safe stream cleanup

## Best Practices

- ✅ Show streaming indicator while generating
- ✅ Support stream cancellation
- ✅ Handle network errors gracefully
- ✅ Implement proper cleanup on unmount
- ✅ Optimize rendering performance
- ✅ Provide visual feedback for stream status

### Performance Best Practices

**Rendering:**
- Use RAF batching for smooth updates (automatic in `useChat`)
- Avoid forcing synchronous layouts during streaming
- Batch DOM updates to prevent reflows

**Concurrency:**
- Connection ID tracking prevents overlapping streams (automatic)
- Always cancel readers on cleanup (automatic)
- Handle rapid user requests gracefully

**Memory:**
- Use message windowing for large conversations (`maxMessages` prop)
- Clean up readers on component unmount (automatic)
- Prevent dangling promises (automatic)

See [Performance Audit Reports](/docs/guides/performance/README.md) for detailed analysis.

## Streaming Protocols

### Server-Sent Events (SSE)
Recommended for most use cases. Simple, reliable, HTTP-based.

### WebSockets
Use for bidirectional communication and low-latency requirements.

### HTTP Streaming
Use for custom protocols or edge deployments.

## When to Use

**StreamBlock**: For structured streaming (code, markdown, JSON)
**StreamingTextRenderer**: For plain text streaming
**StreamCancellation**: To allow users to stop generation
**StreamingExamples**: For reference implementations
