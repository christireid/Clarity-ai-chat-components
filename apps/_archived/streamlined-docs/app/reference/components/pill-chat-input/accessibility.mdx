## ARIA Labels & Roles

### Primary Textarea

The main input textarea includes comprehensive ARIA labeling:

```tsx
<PillChatInput
  value={input}
  onChange={setInput}
  onSubmit={handleSubmit}
  aria-label="Chat input"  // Primary label
  id="chat-input"
  showCharCounter={true}
  maxLength={500}
/>
```

**Rendered ARIA attributes:**

```html
<textarea
  id="chat-input"
  aria-label="Chat input"
  aria-describedby="chat-input-counter"
  role="textbox"
  aria-multiline="true"
/>
```

**Key attributes:**

- `aria-label`: Identifies the purpose of the input
- `aria-describedby`: Associates character counter with input
- `role="textbox"`: Explicit role for assistive technologies
- `aria-multiline="true"`: Indicates multi-line editing capability

### Send/Stop Button

The action button dynamically updates its label based on state:

**Send State:**
```html
<button
  type="button"
  aria-label="Send message"
  disabled={false}
>
  <SendIcon aria-hidden="true" />
</button>
```

**Submitting State:**
```html
<button
  type="button"
  aria-label="Sending..."
  disabled={true}
>
  <SpinnerIcon aria-hidden="true" />
</button>
```

**Stop State (when generating):**
```html
<button
  type="button"
  aria-label="Stop generation"
>
  <StopIcon aria-hidden="true" />
</button>
```

**Key features:**

- Dynamic `aria-label` reflects current state
- `disabled` state communicated to screen readers
- Icons marked `aria-hidden="true"` to avoid redundant announcements

### Attachment Button

When attachment functionality is enabled:

```html
<button
  type="button"
  aria-label="Attach file"
  onClick={handleAttach}
>
  <AttachIcon aria-hidden="true" />
</button>
```

**Customizable label:**

```tsx
// Custom left slot with proper ARIA
<PillChatInput
  leftSlot={
    <button aria-label="Attach images or documents">
      <PaperclipIcon />
    </button>
  }
/>
```

### Character Counter

Live region announces character count changes:

```html
<div
  id="chat-input-counter"
  aria-live="polite"
  class="text-xs"
>
  245/500
</div>
```

**ARIA Live Regions:**

- `aria-live="polite"`: Announces changes without interrupting
- Updates communicated as user types
- Warning states change text color with sufficient contrast

**States and announcements:**

| State | Condition | Text Color | Screen Reader |
|-------|-----------|------------|---------------|
| Normal | < 80% used | `text-muted-foreground/60` | "245 of 500" |
| Warning | 80-100% used | `text-warning` | "425 of 500, approaching limit" |
| Over Limit | > 100% | `text-destructive` | "550 of 500, exceeds limit" |

## Keyboard Navigation

### Tab Order

The component maintains a logical, predictable tab order:

```
1. Attachment Button (if present)
   ↓ Tab
2. Textarea (main input)
   ↓ Tab
3. Send/Stop Button
   ↓ Tab
4. Right Slot Elements (if present)
```

**Implementation:**

All interactive elements are natively focusable with no manual `tabindex` manipulation:

```tsx
// Natural tab order maintained through DOM structure
<div className="flex items-end gap-2">
  {/* 1. Attachment */}
  <button>Attach</button>

  {/* 2. Textarea */}
  <textarea />

  {/* 3. Action button */}
  <button>Send</button>

  {/* 4. Custom right slot */}
  {rightSlot}
</div>
```

### Keyboard Shortcuts

The component supports essential keyboard shortcuts:

#### Enter Key (Submit)

**Behavior:**
- **Enter**: Submit message (if not empty)
- **Shift+Enter**: Insert new line (multi-line input)
- **Enter (when generating)**: Stop generation (if `onStop` provided)

**Code implementation:**

```tsx
const handleKeyDown = (e: KeyboardEvent<HTMLTextAreaElement>) => {
  // Enter without shift to submit
  if (e.key === 'Enter' && !e.shiftKey) {
    e.preventDefault()

    if (isGenerating && onStop) {
      // Stop generation if currently generating
      onStop()
    } else if (canSubmit) {
      // Submit if allowed
      onSubmit()
    }
  }
}
```

**Accessibility considerations:**

- `e.preventDefault()` prevents default form submission
- Allows multi-line input with Shift+Enter
- Provides alternative to mouse interaction for stopping generation

#### Escape Key (Future)

Currently not implemented. Potential use cases:

- Clear input field
- Cancel editing mode
- Close attachment modal

## Screen Reader Support

### Announcements by Component State

The PillChatInput provides contextual information to screen readers through dynamic ARIA labels and live regions.

#### Initial Focus

**Screen reader reads:**

```
"Chat input, textbox, multi-line, empty"
```

**With character counter:**

```
"Chat input, textbox, multi-line, 0 of 500 characters"
```

#### Typing Content

**As user types (no interruption):**

- Character counter updates silently via `aria-live="polite"`
- Only announces on pause or significant change

**When approaching limit (80%):**

```
"400 of 500, approaching character limit"
```

**When exceeding limit:**

```
"550 of 500, exceeds character limit"
```

#### Submitting Message

**Button focus:**

```
"Send message, button"
```

**After clicking/pressing Enter:**

```
"Sending..., button, disabled"
```

**After successful submission:**

```
"Message sent" (if status region provided)
```

#### Stopping Generation

**When AI is generating:**

```
"Stop generation, button"
```

**After stopping:**

```
"Generation stopped" (if status region provided)
```

### Character Counter Implementation

The character counter uses ARIA live regions for non-intrusive announcements:

```tsx
<div
  id={`${id}-counter`}
  aria-live="polite"
  className={cn(
    isOverLimit ? 'text-destructive' :
    isNearLimit ? 'text-warning' :
    'text-muted-foreground/60'
  )}
>
  {charCount}/{maxLength}
</div>
```

**Announcement strategy:**

1. **Polite updates**: Doesn't interrupt current screen reader speech
2. **Debounced**: Updates announced after brief pause in typing
3. **State-aware**: Different styling based on usage level
4. **Associated**: Linked to textarea via `aria-describedby`

### Status Messages (Recommended Pattern)

For complete accessibility, implement a status region in your application:

```tsx
<div role="status" aria-live="polite" className="sr-only">
  {statusMessage}
</div>

<PillChatInput
  value={input}
  onChange={setInput}
  onSubmit={async (value) => {
    setStatusMessage('Sending message...')
    await sendMessage(value)
    setStatusMessage('Message sent successfully')
  }}
  onStop={() => {
    setStatusMessage('Generation stopped')
  }}
/>
```

**Screen reader only class:**

```css
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border-width: 0;
}
```

### Error Handling

When validation errors occur, communicate them accessibly:

```tsx
const [error, setError] = useState('')

<div role="alert" aria-live="assertive">
  {error && <span>{error}</span>}
</div>

<PillChatInput
  aria-describedby={error ? 'input-error' : undefined}
  aria-invalid={!!error}
/>
```

**Error message format:**

```html
<div
  id="input-error"
  role="alert"
  aria-live="assertive"
>
  Message is required
</div>
```

## Focus Management

### Auto-Focus Behavior

The component supports optional auto-focus on mount:

```tsx
<PillChatInput
  autoFocus={true}  // Focus textarea on mount
  value={input}
  onChange={setInput}
  onSubmit={handleSubmit}
/>
```

**Implementation:**

```tsx
// useChatInputFocus hook
React.useEffect(() => {
  if (autoFocus && textareaRef.current) {
    textareaRef.current.focus()
  }
}, [autoFocus, textareaRef])
```

**Use cases:**

- New conversation: Auto-focus for immediate input
- Modal dialogs: Focus input when modal opens
- Page load: Focus for single-page chat applications

**Best practices:**

- Only auto-focus when user expects interaction
- Avoid auto-focus on mobile (virtual keyboard)
- Don't auto-focus in multi-input forms

### Focus Trap Considerations

The PillChatInput does not implement focus trapping by default. If used in a modal or dialog, implement focus trap at the container level:

```tsx
import { useFocusTrap } from '@clarity-chat/primitives'

function ChatModal({ isOpen, onClose }) {
  const modalRef = useRef<HTMLDivElement>(null)
  useFocusTrap(modalRef, isOpen)

  return (
    <div ref={modalRef} role="dialog" aria-modal="true">
      <h2 id="modal-title">New Conversation</h2>

      <PillChatInput
        autoFocus={true}
        aria-labelledby="modal-title"
      />

      <button onClick={onClose}>Cancel</button>
    </div>
  )
}
```

### Focus Restoration

When removing or hiding the component, restore focus appropriately:

```tsx
function ConversationView() {
  const [showInput, setShowInput] = useState(true)
  const returnFocusRef = useRef<HTMLButtonElement>(null)

  const handleRemove = () => {
    setShowInput(false)
    returnFocusRef.current?.focus()
  }

  return (
    <>
      <button ref={returnFocusRef}>
        New Message
      </button>

      {showInput && (
        <PillChatInput
          onSubmit={(value) => {
            sendMessage(value)
            handleRemove()
          }}
        />
      )}
    </>
  )
}
```

### Focus States

The component tracks and communicates focus state:

```tsx
// Visual feedback when focused
const { isFocused, handleFocus, handleBlur } = useChatInputFocus({
  autoFocus,
  textareaRef,
})

// Container applies focus styles
<div className={cn(
  'chat-input-pill',
  isFocused && 'ring-2 ring-primary/20'
)}>
```

**States tracked:**

- `isFocused`: Textarea has focus
- `disabled`: Input is disabled
- `isSubmitting`: Message is being sent

## Reduced Motion Support

The PillChatInput respects the `prefers-reduced-motion` media query, disabling or simplifying animations for users who may experience motion sickness or vestibular disorders.

### Detection

Reduced motion preference is detected via the `useReducedMotion` hook:

```tsx
import { useReducedMotion } from '@clarity-chat/primitives'

function PillChatInput({ disableAnimations = false, ...props }) {
  const prefersReducedMotion = useReducedMotion() || disableAnimations

  // Pass to animated components
  return (
    <ChatActionButton
      disableAnimations={prefersReducedMotion}
      {...buttonProps}
    />
  )
}
```

### Animation Adjustments

When reduced motion is preferred, animations are simplified or removed:

#### Send/Stop Button Transitions

**Normal mode:**

```tsx
<motion.button
  initial={{ opacity: 0, scale: 0.8 }}
  animate={{ opacity: 1, scale: 1 }}
  exit={{ opacity: 0, scale: 0.8 }}
  transition={{
    duration: 0.15,  // Fast animation
    ease: 'easeOut'
  }}
/>
```

**Reduced motion mode:**

```tsx
<motion.button
  initial={{ opacity: 1 }}  // No scale animation
  animate={{ opacity: 1 }}
  exit={{ opacity: 0 }}
  transition={{
    duration: 0.05,  // Instant transition
  }}
/>
```

#### Focus Glow Effect

**Normal mode:**

```css
.chat-input-pill:focus-within {
  transition: box-shadow 0.2s ease-out;
  box-shadow: 0 0 0 3px hsl(var(--primary) / 0.1);
}
```

**Reduced motion mode:**

```css
@media (prefers-reduced-motion: reduce) {
  .chat-input-pill:focus-within {
    transition: none;  /* Instant state change */
  }
}
```

#### Auto-Resize Animation

**Normal mode:**

```tsx
// Smooth height transition
textarea.style.transition = 'height 0.1s ease-out'
textarea.style.height = `${newHeight}px`
```

**Reduced motion mode:**

```tsx
// Instant resize
textarea.style.transition = 'none'
textarea.style.height = `${newHeight}px`
```

### Manual Override

Developers can disable animations explicitly:

```tsx
<PillChatInput
  disableAnimations={true}  // Force disable all animations
  value={input}
  onChange={setInput}
  onSubmit={handleSubmit}
/>
```

**Use cases:**

- Performance optimization on low-end devices
- Testing with animations disabled
- User preference settings in application

### WCAG Success Criterion

**WCAG 2.1: 2.3.3 Animation from Interactions (Level AAA)**

The component respects user preferences for reduced motion, meeting Level AAA guidelines by:

1. Detecting system preference via media query
2. Providing manual override option
3. Maintaining functionality when animations are disabled
4. Using instant state changes instead of animated transitions

## High Contrast Mode

The PillChatInput is compatible with Windows High Contrast Mode and forced-colors media query.

### System Colors

In high contrast mode, the component uses system colors:

```css
@media (forced-colors: active) {
  .chat-input-pill {
    border: 1px solid ButtonText;
    background-color: Field;
    color: FieldText;
  }

  .chat-input-pill:focus-within {
    outline: 2px solid Highlight;
    outline-offset: 2px;
  }

  button {
    border: 1px solid ButtonText;
    background-color: ButtonFace;
    color: ButtonText;
  }

  button:disabled {
    border-color: GrayText;
    color: GrayText;
  }
}
```

**System color keywords:**

- `Field`: Background for input fields
- `FieldText`: Text in input fields
- `ButtonFace`: Button background
- `ButtonText`: Button text and borders
- `Highlight`: Focus indicator color
- `GrayText`: Disabled state text

### Border Visibility

Ensure borders are visible in high contrast mode:

```css
.chat-input-pill {
  /* Regular mode */
  border: 1px solid transparent;
  box-shadow: 0 2px 8px rgba(0, 0, 0, 0.08);

  /* High contrast mode */
  @media (forced-colors: active) {
    border-color: ButtonText;
    box-shadow: none;  /* Shadows ignored in HC mode */
  }
}
```

### Icon Visibility

Icons use `currentColor` for automatic color adaptation:

```tsx
<svg fill="currentColor" stroke="currentColor">
  <path d="..." />
</svg>
```

**High contrast behavior:**

- Icons inherit text color
- Maintain visibility against background
- Use system colors automatically

### Testing High Contrast Mode

**Windows 10/11:**

1. Press `Left Alt + Left Shift + Print Screen`
2. Or: Settings → Accessibility → High Contrast
3. Choose a high contrast theme

**Chrome DevTools:**

1. Open DevTools (F12)
2. Open Command Palette (Ctrl+Shift+P)
3. Type "Emulate CSS media feature forced-colors"
4. Select "forced-colors: active"

### Custom Implementation Example

To implement custom keyboard shortcuts:

```tsx
function EnhancedPillChatInput(props) {
  const handleKeyDown = (e: React.KeyboardEvent) => {
    // Escape to clear
    if (e.key === 'Escape') {
      props.onChange('')
      e.preventDefault()
    }

    // Ctrl+Enter to submit without clearing
    if (e.key === 'Enter' && e.ctrlKey) {
      props.onSubmit(props.value, { clear: false })
      e.preventDefault()
    }
  }

  return (
    <div onKeyDown={handleKeyDown}>
      <PillChatInput {...props} />
    </div>
  )
}
```

**Accessibility notes for custom shortcuts:**

1. Document shortcuts in UI or help text
2. Don't override standard shortcuts (Ctrl+C, Ctrl+V)
3. Provide alternatives to shortcuts (buttons)
4. Test with screen readers (may conflict)

## Best Practices Summary

### Quick Checklist

- [x] Always provide descriptive `aria-label`
- [x] Enable `showCharCounter` for length-limited inputs
- [x] Test with keyboard-only navigation
- [x] Test with at least one screen reader
- [x] Respect `prefers-reduced-motion`
- [x] Ensure 4.5:1 text contrast ratio
- [x] Provide visual focus indicators
- [x] Use semantic HTML (`<textarea>`, `<button>`)
- [x] Associate labels with controls
- [x] Communicate state changes to screen readers

### Common Mistakes to Avoid

❌ **Don't:**

- Use `<div>` with `onClick` instead of `<button>`
- Remove focus indicators with `outline: none`
- Set `tabindex="-1"` on focusable elements
- Rely solely on color to indicate state
- Use `aria-label` on non-interactive elements
- Ignore character counter for screen readers
- Force animations when reduced motion preferred
- Use low contrast for placeholder text

✅ **Do:**

- Use semantic HTML elements
- Provide visible focus indicators
- Include text alternatives for icons
- Test with multiple screen readers
- Document keyboard shortcuts
- Respect user preferences (motion, contrast)
- Communicate state changes accessibly
- Maintain logical tab order
