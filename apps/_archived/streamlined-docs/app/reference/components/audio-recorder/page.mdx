# AudioRecorder

Browser-based audio recording component with waveform visualization, noise cancellation, and format conversion. Built on the Web Audio API with 95% browser compatibility and professional-grade audio processing.

## Features

- **Real-time Waveform Visualization**: Live audio amplitude display with 60-bar animated waveform
- **Advanced Audio Processing**: Noise cancellation, echo cancellation, and auto-gain control
- **Multiple Format Support**: WebM, MP3, WAV, OGG, and FLAC (browser-dependent)
- **Voice Activity Detection**: Automatic pause/resume during silence to save space
- **Accessible UI**: Full ARIA support with keyboard navigation and screen reader announcements
- **Pause/Resume**: Control recording flow with optional pause functionality
- **Duration Controls**: Min/max recording duration with visual countdown timer
- **Audio Level Meter**: Real-time input level visualization with color gradient

function AdvancedRecorder() {

      setIsProcessing(false)
    }
  }

    // Use amplitude for custom visualizations
    if (amplitude > 0.8) {
      console.log('Loud audio detected!')
    }

        showDuration={true}

        onStop={handleStop}
        onAmplitudeChange={handleAmplitudeChange}
        onDurationChange={(duration) => console.log('Duration:', duration)}
        theme="dark"
      />

      {isProcessing && <p>Processing audio...</p>}

      {audioUrl && (

## MediaRecorder API Details

The AudioRecorder component is built on the **MediaRecorder API**, which provides native audio recording in the browser without plugins.

### How It Works

1. **Request Microphone Access**: Uses `navigator.mediaDevices.getUserMedia()` to request permission
2. **Create MediaRecorder**: Initializes MediaRecorder with specified MIME type and bitrate
3. **Capture Audio Chunks**: Records audio data in chunks (Blob objects)
4. **Process on Stop**: Combines chunks into final Blob when recording stops
5. **Create Object URL**: Generates blob:// URL for immediate playback

### Audio Processing Pipeline

```
Microphone Input
    ↓
MediaStream (getUserMedia)
    ↓
Audio Constraints Applied
    ├─ Echo Cancellation
    ├─ Noise Suppression
    ├─ Auto Gain Control
    └─ Sample Rate/Channels
    ↓
Web Audio Context (optional)
    ├─ AnalyserNode (waveform)
    └─ Amplitude Detection
    ↓
MediaRecorder
    ├─ Codec Selection
    ├─ Bitrate Control
    └─ Chunk Recording
    ↓
Final Audio Blob
    ├─ Object URL Creation
    └─ onStop Callback
```

### MIME Type Detection

The component automatically detects supported MIME types:

```typescript
// Example detection flow
const formatMap = {
  webm: ['audio/webm;codecs=opus', 'audio/webm'],
  ogg: ['audio/ogg;codecs=opus', 'audio/ogg'],
  wav: ['audio/wav', 'audio/wave'],
  mp3: ['audio/mp3', 'audio/mpeg'],
  flac: ['audio/flac'],
}

// Check support
for (const type of formatMap[outputFormat]) {
  if (MediaRecorder.isTypeSupported(type)) {
    return type // Use first supported type
  }
}

// Fallback to WebM
return 'audio/webm'
```

### Audio Constraints

The component applies these MediaStream constraints:

```typescript
{
  audio: {
    channelCount: 1 | 2,           // Mono or stereo
    sampleRate: 48000,             // Default device rate
    echoCancellation: boolean,     // Reduce echo
    noiseSuppression: boolean,     // Reduce background noise
    autoGainControl: boolean,      // Normalize volume
  }
}
```

### Voice Activity Detection

When enabled, the component monitors audio amplitude to detect speech:

```typescript
// Simplified VAD logic
const rms = calculateRMS(audioData)
const amplitude = rms * 2 // Normalized 0-1

if (amplitude < silenceThreshold) {
  // Pause during silence
  mediaRecorder.pause()
} else if (amplitude >= silenceThreshold && isPaused) {
  // Resume on voice
  mediaRecorder.resume()
}
```

## Accessibility

The AudioRecorder component follows WCAG 2.1 AA guidelines:

### Keyboard Navigation

- **Tab**: Focus next control
- **Shift + Tab**: Focus previous control
- **Enter/Space**: Activate focused button
- **Escape**: Stop recording (when focused)

### ARIA Support

- All buttons have descriptive `aria-label` attributes
- Recording status announced via `aria-live="polite"` region
- Icons marked with `aria-hidden="true"` to avoid redundancy
- Disabled states indicated with `aria-disabled`

### Screen Reader Announcements

```tsx
// Live region for status updates
<div role="status" aria-live="polite" className="sr-only">
  {isRecording && !isPaused && `Recording: ${formatDuration(duration)}`}
  {isPaused && 'Recording paused'}
  {!isRecording && 'Ready to record'}
</div>
```

### Color Contrast

All UI elements meet WCAG AA standards:
- Text: 4.5:1 contrast ratio minimum
- Interactive elements: 3:1 contrast ratio minimum
- Focus indicators: 3:1 contrast ratio minimum

## Performance Considerations

### Memory Management

The component automatically cleans up resources:

- Stops MediaStream tracks on unmount
- Closes AudioContext to free resources
- Cancels animation frames
- Clears intervals

### Large Recordings

For long recordings (>10 minutes), consider:

```tsx
<AudioRecorder
  maxDuration={3600} // 1 hour
  onDataAvailable={(chunk) => {
    // Process chunks incrementally
    uploadChunk(chunk)
  }}
  onStop={(blob) => {
    // Final processing
    finalizeRecording(blob)
  }}
/>
```

### Virtual Scrolling

When displaying many recordings, use virtual scrolling:

```tsx
import { useVirtualizer } from '@tanstack/react-virtual'

function RecordingList({ recordings }) {
  const virtualizer = useVirtualizer({
    count: recordings.length,
    getScrollElement: () => parentRef.current,
    estimateSize: () => 100,
  })

  return (
    <div ref={parentRef} className="h-96 overflow-auto">
      {virtualizer.getVirtualItems().map((item) => (
        <RecordingItem key={item.key} recording={recordings[item.index]} />
      ))}
    </div>
  )
}
```
