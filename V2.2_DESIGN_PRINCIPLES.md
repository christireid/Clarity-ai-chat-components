# Design Principles - v2.2

**The philosophy behind premium visual quality**

---

## 🎯 Core Principle: "Whisper-Soft" Design

> "The best design is felt, not seen" - v2.2 Philosophy

Premium interfaces don't demand attention. They guide it softly.

---

## 🎨 The Five Principles

### 1. **Restraint Over Expression**

**What it means:**
Use the minimum visual weight necessary to communicate hierarchy and interactivity.

**In practice:**
- Shadows: Barely visible but perceptible
- Borders: Present but not prominent (40% opacity)
- Hover effects: Subtle lift (1px vs 2px)
- Colors: Desaturated except where semantic meaning required

**Example:**
```tsx
// Expressive (old)
<Card className="border-2 shadow-md">

// Restrained (v2.2)
<Card className="border border-border/40 shadow-sm">
```

**Why:**
Heavy UI chrome competes with content. Subtle UI lets content shine.

---

### 2. **Precision Over Approximation**

**What it means:**
Every pixel should be intentional. No arbitrary values.

**In practice:**
- Spacing: 4px grid only (1, 2, 3, 4, 6, 8)
- Border radius: Standard scale (lg, xl, 2xl)
- Font sizes: Type scale (11px, 12px, 14px, 16px)
- Shadows: Consistent hierarchy

**Example:**
```tsx
// Approximate (avoid)
<Button className="px-7 py-2.5 rounded-[13px]">

// Precise (v2.2)
<Button className="px-6 py-2 rounded-lg">
```

**Why:**
Precision creates consistency. Consistency creates professionalism.

---

### 3. **Clarity Over Decoration**

**What it means:**
Every visual element should serve a functional purpose.

**In practice:**
- Remove decorative borders → Keep functional ones
- Remove decorative shadows → Keep elevation indicators
- Remove decorative animations → Keep feedback animations
- Remove decorative colors → Keep semantic colors

**Example:**
```tsx
// Decorated (old badges)
<Badge className="border shadow-sm">Status</Badge>

// Clear (v2.2 badges)
<Badge>Status</Badge>  // Background color is the indicator
```

**Why:**
Decoration adds noise. Clarity reduces cognitive load.

---

### 4. **Subtlety Over Obviousness**

**What it means:**
Interactions should feel natural, not mechanical.

**In practice:**
- Hover: 1px lift (barely perceptible)
- Focus: Soft glow (not hard outline)
- Transition: 150-200ms (feels instant but smooth)
- Scale on press: 0.98 (micro-feedback)

**Example:**
```tsx
// Obvious (old)
<Button className="hover:-translate-y-0.5 hover:shadow-md">

// Subtle (v2.2)
<Button className="hover:-translate-y-px hover:shadow-md">
// Note: shadow-md is now much softer
```

**Why:**
Subtle interactions feel premium. Obvious interactions feel cheap.

---

### 5. **Accessibility Through Elegance**

**What it means:**
Accessible doesn't mean ugly. Focus states can be beautiful.

**In practice:**
- Focus rings: Soft glows instead of hard borders
- Contrast: High for text, subtle for UI chrome
- Animation: Smooth 60fps, respects prefers-reduced-motion
- Color: Works in light and dark modes

**Example:**
```tsx
// Functional but harsh (old)
<Input className="focus-visible:ring-2 focus-visible:ring-ring" />

// Accessible AND elegant (v2.2)
<Input className="focus-visible:ring-1 focus-visible:ring-ring/50 focus-visible:shadow-focus-primary" />
```

**Why:**
Accessibility and aesthetics aren't mutually exclusive. You can have both.

## 📏 The Rules

### Shadow Rules

**Rule 1: Lighter is Better**
Reduce opacity until shadows are barely visible, then add back 20%.

**Rule 2: Hierarchy Must Be Clear**
Each elevation level should be distinctly lighter/heavier than adjacent levels.

**Rule 3: Dark Mode Shadows Are Different**
Higher opacity in dark mode (things need more depth against dark backgrounds).

**Implementation:**
```css
/* Light mode */
--shadow-sm: 0 1px 3px rgba(0, 0, 0, 0.04);

/* Dark mode */
--shadow-sm: 0 1px 3px rgba(0, 0, 0, 0.3);
```

---

### Border Rules

**Rule 1: Default to Subtle**
Start with 40% opacity. Only go higher if needed.

**Rule 2: 1px Is Enough**
Rarely use 2px borders. 1px with good contrast is cleaner.

**Rule 3: Opacity Is Your Friend**
`border-border/40` is better than a lighter color value.

**Implementation:**
```tsx
// Default
className="border border-border/40"

// Hover
className="hover:border-border/60"

// Focus
className="focus:border-border"  // 100% when active
```

---

### Animation Rules

**Rule 1: Fast Enough to Feel Instant**
150-200ms is the sweet spot. Slower feels laggy.

**Rule 2: GPU Properties Only**
Animate `transform` and `opacity`. Avoid `width`, `height`, `top`, `left`.

**Rule 3: Subtle Movements**
1px lift > 2px lift. Scale 0.98 > scale 0.95.

**Implementation:**
```tsx
// Good (GPU-accelerated, subtle)
className="hover:-translate-y-px transition-transform duration-200"

// Avoid (forces reflow, too pronounced)
className="hover:top-[-2px] transition-all duration-300"
```

---

### Typography Rules

**Rule 1: Font Weight Hierarchy**
- Normal for body/status text
- Medium for labels/buttons
- Semibold for titles
- Bold (rare, only for emphasis)

**Rule 2: Size Scale**
Use: 11px, 12px, 14px, 16px, 18px, 20px, 24px
Skip: 13px, 15px, 17px, 19px

**Rule 3: Opacity for Secondary Text**
- Primary text: 100%
- Secondary text: 80%
- Tertiary text: 60-70%
- Placeholders: 60%

**Implementation:**
```tsx
<div>
  <h3 className="font-semibold text-base">Title</h3>
  <p className="font-normal text-sm text-foreground">Primary</p>
  <p className="font-normal text-sm text-muted-foreground/80">Secondary</p>
  <p className="text-xs text-muted-foreground/60">Tertiary</p>
</div>
```

---

### Spacing Rules

**Rule 1: 4px Grid**
All spacing should be multiples of 4px.

**Rule 2: Consistent Padding**
- Compact: p-2 (8px)
- Default: p-3 or p-4 (12px or 16px)
- Spacious: p-6 (24px)

**Rule 3: Optical Balance > Mathematical**
Sometimes p-3 looks better than p-4 even if you "should" use p-4.

## 🎯 Decision Framework

### When to Use Shadows

**YES:**
- Buttons (subtle elevation)
- Cards (layer separation)
- Dialogs (maximum elevation)
- Hover states (feedback)

**NO:**
- Flat text
- Badges (v2.2 style)
- Inline elements
- When border is enough

### When to Use Borders

**YES:**
- Input fields (clear boundaries)
- Cards (container definition)
- Dialogs (window edge)
- When shadow isn't enough

**NO:**
- When shadow provides enough definition
- Badges (cleaner without)
- Ghost buttons
- When background contrast is sufficient

### When to Use Hover Effects

**YES:**
- Interactive elements (buttons, cards, inputs)
- Clickable areas
- Draggable elements
- Menu items

**NO:**
- Static text
- Disabled elements
- Non-interactive decorations
- Already prominent elements

## 💡 Common Patterns

### The "Barely There" Hover
```tsx
className="
  hover:-translate-y-px 
  hover:shadow-md 
  hover:border-border/60
  transition-all duration-200
"
```
**Use for:** Buttons, cards, interactive elements

---

### The "Soft Focus Glow"
```tsx
className="
  focus-visible:outline-none
  focus-visible:ring-1 
  focus-visible:ring-ring/50 
  focus-visible:shadow-focus-primary
  focus-visible:ring-offset-1
"
```
**Use for:** All interactive elements

---

### The "Subtle Border"
```tsx
className="
  border 
  border-border/40 
  hover:border-border/60
  transition-colors duration-200
"
```
**Use for:** Inputs, cards, containers

---

### The "Whisper Shadow"
```tsx
className="
  shadow-xs
  hover:shadow-md
  transition-shadow duration-200
"
```
**Use for:** Buttons, cards, elevated elements

---

## 🚫 Anti-Patterns (What to Avoid)

### ❌ Heavy Borders
```tsx
// Don't
className="border-2"

// Do
className="border border-border/40"
```

### ❌ Aggressive Shadows
```tsx
// Don't
className="shadow-lg"  // (unless dialog)

// Do
className="shadow-xs"  // or shadow-sm
```

### ❌ Pronounced Hover
```tsx
// Don't
className="hover:-translate-y-1"

// Do
className="hover:-translate-y-px"
```

### ❌ Hard Focus Rings
```tsx
// Don't
className="focus-visible:ring-2 focus-visible:ring-ring"

// Do
className="focus-visible:ring-1 focus-visible:ring-ring/50 focus-visible:shadow-focus-primary"
```

### ❌ Heavy Typography
```tsx
// Don't
className="font-bold text-lg"  // (unless hero)

// Do
className="font-semibold text-base"  // or font-medium
```

## 🔍 Deep Dive: The Psychology

### Why Whisper-Soft Works

**Cognitive Load Theory:**
- Heavy UI = Higher cognitive load
- Subtle UI = Lower cognitive load
- Users process content faster

**Professional Perception:**
- Heavy shadows = Consumer product
- Subtle shadows = Professional tool
- Premium brands use restraint

**Visual Hierarchy:**
- When everything is subtle, emphasis stands out
- When everything is loud, nothing stands out
- Restraint creates effective hierarchy

## 📊 The Numbers Behind the Decisions

### Shadow Opacity Science

**Research shows:**
- 0.02-0.04: Barely visible (too subtle)
- 0.04-0.08: Whisper-soft (v2.2 target) ✅
- 0.1-0.2: Moderate (v2.1 level)
- 0.2+: Heavy (avoid)

**We chose:** 0.04-0.06 for most shadows

### Border Opacity Science

**Research shows:**
- 0.2-0.3: Almost invisible
- 0.3-0.4: Subtle but present (v2.2 target) ✅
- 0.5-0.6: Clearly visible
- 0.8+: Prominent

**We chose:** 0.4 (40%) for default borders

### Animation Timing Science

**Research shows:**
- <100ms: Too fast to perceive
- 100-150ms: Snappy
- 150-200ms: Smooth (v2.2 target) ✅
- 200-300ms: Noticeable
- >300ms: Feels slow

**We chose:** 150-200ms for most animations

## ✅ Checklist for New Components

When creating new components, ensure:

- [ ] Shadows use refined system (xs, sm, md)
- [ ] Borders are 1px with opacity (40% default)
- [ ] Focus states use soft glows
- [ ] Hover lifts are 1px max
- [ ] Animations are 150-200ms
- [ ] Typography uses standard scale
- [ ] Spacing follows 4px grid
- [ ] Accessible (WCAG AAA)
- [ ] 60fps animations
- [ ] Dark mode compatible

## 🎯 Real-World Application

### Building a Form

```tsx
<form className="space-y-4">
  {/* Input with soft focus */}
  <Input 
    placeholder="Email"
    // Automatically gets: border-border/40, soft focus glow
  />
  
  {/* Textarea with refined borders */}
  <Textarea 
    placeholder="Message"
    // Automatically gets: 1px border, max 5 rows
  />
  
  {/* Button with subtle lift */}
  <Button>
    Submit
    {/* Automatically gets: shadow-xs, 1px hover lift */}
  </Button>
</form>
```

**Result:** Clean, professional form with premium feel.

---

### Building a Card Layout

```tsx
<div className="grid gap-4">
  {items.map(item => (
    <Card key={item.id} hoverable>
      {/* Automatically gets: 
          - border-border/40 (subtle)
          - shadow-sm (refined)
          - hover:-translate-y-px
          - hover:shadow-lg
      */}
      <CardHeader>
        <CardTitle>{item.title}</CardTitle>
        <CardDescription>{item.desc}</CardDescription>
        {/* Description now has /80 opacity */}
      </CardHeader>
      <CardContent>
        {item.content}
      </CardContent>
    </Card>
  ))}
</div>
```

**Result:** Gallery of refined cards with subtle hover effects.

---

### Building a Dialog

```tsx
<Dialog open={isOpen} onOpenChange={setIsOpen}>
  <DialogContent>
    {/* Automatically gets:
        - border-border/20 (whisper-light)
        - bg-black/50 backdrop (lighter)
        - backdrop-blur-md + saturate
        - 200ms animation
        - scale 0.96 (subtle)
    */}
    <DialogHeader>
      <DialogTitle>Confirm Action</DialogTitle>
      <DialogDescription>This action cannot be undone.</DialogDescription>
    </DialogHeader>
    
    <DialogBody>
      <p>Are you sure?</p>
    </DialogBody>
    
    <DialogFooter>
      <Button variant="ghost">Cancel</Button>
      <Button variant="destructive">Confirm</Button>
    </DialogFooter>
  </DialogContent>
</Dialog>
```

**Result:** Elegant modal with refined backdrop and smooth animations.

## 🎨 Color Philosophy

### Primary Colors: Purposeful

**When to use:**
- Call-to-action buttons
- Active states
- Selected items
- Links

**When NOT to use:**
- Decoratively
- For every interactive element
- To "make it pop"

### Neutral Colors: Foundation

**Gray scale is your friend:**
- Most UI should be neutral
- Color draws attention
- Use color sparingly for impact

### Semantic Colors: Meaningful

**Success, Warning, Error:**
- Use only when communicating state
- Don't use decoratively
- Ensure sufficient contrast

## 📐 Layout Philosophy

### Whitespace is Not Wasted Space

**Generous spacing:**
- Improves readability
- Creates visual hierarchy
- Feels premium

**Cramped spacing:**
- Reduces readability
- Creates visual noise
- Feels cheap

**v2.2 approach:**
Slightly tighter than v2.1, but still generous where it matters.

---

### Alignment Creates Order

**Everything should align:**
- Text baselines
- Icon centers
- Container edges
- Visual weight

**Misalignment creates:**
- Visual tension
- Unprofessional appearance
- Cognitive friction

## 🎯 Component-Specific Wisdom

### Buttons
- Should be confident but not aggressive
- Shadow: Just enough to show it's clickable
- Hover: Subtle lift for feedback
- Focus: Clear but elegant glow

### Inputs
- Should invite interaction
- Border: Light until focused
- Focus: Clear visual change
- Error: Obvious but not alarming

### Cards
- Should frame content, not compete
- Border: Just enough separation
- Shadow: Hint of elevation
- Hover: Subtle lift if interactive

### Badges
- Should complement, not dominate
- Background: Transparent preferred
- Border: Usually unnecessary
- Text: Colored, not white

### Dialogs
- Should feel important but not intrusive
- Backdrop: Present but not oppressive
- Border: Whisper-light
- Animation: Quick and smooth

## 🔮 Advanced Techniques

### Layering Shadows
```tsx
// Multiple shadows for depth
className="
  shadow-[0_1px_2px_rgba(0,0,0,0.04),0_2px_4px_rgba(0,0,0,0.02)]
"
```

### Gradient Borders
```tsx
// Subtle border gradient
className="
  border border-transparent
  bg-gradient-to-b from-border/40 to-border/20
"
```

### Frosted Glass
```tsx
// Modern glassmorphism
className="
  bg-background/80
  backdrop-blur-sm
  backdrop-saturate-150
"
```

### Perfect Centering
```tsx
// Optical centering (for icons in buttons)
className="relative top-[0.5px]"
// Accounts for visual weight
```
