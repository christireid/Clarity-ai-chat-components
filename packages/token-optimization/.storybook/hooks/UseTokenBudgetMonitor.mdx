# useTokenBudgetMonitor

Real-time token budget tracking with threshold-based warnings and automatic trimming. Prevents context overflow and provides immediate cost awareness.

## Overview

`useTokenBudgetMonitor` is your comprehensive solution for managing token budgets in conversational AI applications. It tracks conversations, monitors usage against configurable limits, and provides real-time status updates with automatic content trimming.

**When to use:**
- Track token usage across multi-turn conversations
- Prevent exceeding model context windows
- Implement usage quotas and limits
- Provide visual feedback (safe, warning, critical, exceeded)
- Auto-trim conversation history to stay within budget
- Monitor and control API costs in real-time

**When not to use:**
- If you only need basic counting → use `useTokenCount`
- If you need compression or caching → use `useTokenOptimization`
- If you need model routing → use `useModelRouter`

## Basic Usage

```tsx
import { useTokenBudgetMonitor } from '@clarity-chat/token-optimization/react'

function ChatWithBudget() {
  const [messages, setMessages] = useState([])

  const { usage, isWarning, isCritical, updateMessages } = useTokenBudgetMonitor({
    maxInputTokens: 128000,
    reservedForOutput: 4096,
    warningThreshold: 0.8,
    criticalThreshold: 0.95,
  })

  useEffect(() => {
    updateMessages(messages)
  }, [messages])

  return (
    <div>
      <ConversationHistory messages={messages} />
      <TokenUsageBar
        current={usage.current}
        max={usage.effectiveMax}
        status={usage.status}
      />
      {isWarning && <Alert severity="warning">Approaching token limit</Alert>}
      {isCritical && <Alert severity="error">Critical: Consider trimming history</Alert>}
      <p>{usage.utilizationPercent.toFixed(1)}% of budget used</p>
    </div>
  )
}
```

## API Reference

### Parameters

```tsx
useTokenBudgetMonitor(
  config: TokenBudgetConfig
): TokenBudgetMonitorReturn
```

#### `config: TokenBudgetConfig`

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `maxInputTokens` | `number` | required | Maximum input tokens for the model (e.g., 128000 for GPT-4) |
| `warningThreshold` | `number` | `0.8` | Warning threshold as decimal (0.8 = 80%) |
| `criticalThreshold` | `number` | `0.95` | Critical threshold as decimal (0.95 = 95%) |
| `reservedForOutput` | `number` | `4096` | Tokens reserved for output response |
| `model` | `ModelName` | `undefined` | Model name for accurate token counting |
| `onWarning` | `(usage) => void` | `undefined` | Callback when warning threshold is crossed |
| `onCritical` | `(usage) => void` | `undefined` | Callback when critical threshold is crossed |
| `onExceeded` | `(usage) => void` | `undefined` | Callback when exceeded (over 100%) |
| `autoTrim` | `boolean` | `false` | Auto-trigger trimming at critical threshold |
| `onAutoTrim` | `(result) => void` | `undefined` | Callback after auto-trim occurs |
| `debounceMs` | `number` | `300` | Debounce delay for token counting in ms |
| `useAccurateTokenization` | `boolean` | `false` | Use accurate tokenization (slower but precise) |

### Return Value

```tsx
{
  usage: TokenUsage           // Current token usage metrics
  isWarning: boolean          // Whether in warning state
  isCritical: boolean         // Whether in critical state
  isExceeded: boolean         // Whether exceeded budget
  wouldExceed: (n: number) => boolean  // Check if adding N tokens would exceed
  calculateTokens: (text: string) => Promise<number>  // Calculate tokens for text
  updateMessages: (messages: BudgetMessage[]) => void  // Update and recalculate
  trimToCritical: () => TrimResult | null  // Manually trigger trim
  reset: () => void           // Reset monitor state
  lastTrimResult: TrimResult | null  // Last trim result if any
  isCalculating: boolean      // Whether currently calculating
}
```

#### `TokenUsage` Object

```tsx
{
  current: number             // Current tokens used
  max: number                 // Maximum tokens allowed
  available: number           // Available tokens remaining
  utilizationPercent: number  // Utilization as percentage (0-100)
  exceededPercent: number     // Percentage over budget (0 if not exceeded)
  status: 'safe' | 'warning' | 'critical' | 'exceeded'
  reservedForOutput: number   // Tokens reserved for output
  effectiveMax: number        // Effective max for input (max - reserved)
}
```

#### `BudgetMessage` Format

```tsx
{
  role: 'user' | 'assistant' | 'system'
  content: string
  tokens?: number             // Pre-computed token count (optional)
  trimmable?: boolean         // Whether this can be trimmed (default: true)
  priority?: number           // Priority for trimming (lower = trim first)
}
```

```tsx
import { useTokenBudgetMonitor } from '@clarity-chat/token-optimization/react'

function MonitoredChat() {

        type: 'error',
        message: `Exceeded budget by ${usage.exceededPercent.toFixed(1)}%`
      }])
    },

    updateMessages(messages)
  }, [messages])

  return (
    <div>
      <AlertList alerts={alerts} />
      <ConversationView messages={messages} />
    </div>
  )
```

### With Auto-Trimming

```tsx
import { useTokenBudgetMonitor } from '@clarity-chat/token-optimization/react'

function AutoTrimChat() {
  const [messages, setMessages] = useState([])
  const [trimHistory, setTrimHistory] = useState([])

  const { usage, updateMessages, lastTrimResult } = useTokenBudgetMonitor({
    maxInputTokens: 128000,
    reservedForOutput: 4096,
    criticalThreshold: 0.95,
    autoTrim: true, // Automatically trim when critical

    onAutoTrim: (result) => {
      console.log('Auto-trimmed:', result.tokensRemoved, 'tokens')
      console.log('Removed messages:', result.removedItems)

      setTrimHistory(prev => [...prev, {
        timestamp: new Date(),
        tokensRemoved: result.tokensRemoved,
        messagesRemoved: result.removedItems.length,
      }])

      // Update messages with trimmed content
      const trimmedMessages = result.trimmedContent.map((content, i) => ({
        role: messages[i].role,
        content,
      }))
      setMessages(trimmedMessages)
    },
  })

  useEffect(() => {
    updateMessages(messages)
  }, [messages])

  return (
    <div>
      <ConversationView messages={messages} />

      {lastTrimResult && (
        <div className="trim-notification">
          Auto-trimmed {lastTrimResult.tokensRemoved} tokens
          ({lastTrimResult.removedItems.length} messages)
        </div>
      )}

      {trimHistory.length > 0 && (
        <details>
          <summary>Trim History ({trimHistory.length})</summary>
          <ul>
            {trimHistory.map((trim, i) => (
              <li key={i}>
                {trim.timestamp.toLocaleTimeString()}:
                Removed {trim.tokensRemoved} tokens ({trim.messagesRemoved} messages)
              </li>
            ))}
          </ul>
        </details>
      )}
    </div>
  )
}
```

```tsx
import { useTokenBudgetMonitor } from '@clarity-chat/token-optimization/react'

function ManualTrimChat() {

            Trim Conversation History
          </button>
```

```tsx
function PrioritizedChat() {

    addMessage('user', content, 5)  // priority: 5 (keep longer)
  }

  const handleOldMessage = (content) => {
    addMessage('assistant', content, 1)  // priority: 1 (trim first)
  }

  useEffect(() => {
    updateMessages(messages)
  }, [messages])

  return (
    <div>
      <ConversationView messages={messages} />
      <p>{usage.current} / {usage.effectiveMax} tokens</p>
    </div>
  )
}
```

### With Pre-Send Validation

```tsx
import { useTokenBudgetMonitor } from '@clarity-chat/token-optimization/react'

function ValidatedChatInput() {
  const [messages, setMessages] = useState([])
  const [draft, setDraft] = useState('')

  const { usage, wouldExceed, calculateTokens, updateMessages } = useTokenBudgetMonitor({
    maxInputTokens: 128000,
    reservedForOutput: 4096,
  })

  const [draftTokens, setDraftTokens] = useState(0)

  useEffect(() => {
    updateMessages(messages)
  }, [messages])

  useEffect(() => {
    calculateTokens(draft).then(setDraftTokens)
  }, [draft, calculateTokens])

  const canSend = !wouldExceed(draftTokens)

  const handleSend = () => {
    if (!canSend) {
      alert('Message would exceed token budget')
      return
    }

    setMessages(prev => [...prev, {
      role: 'user',
      content: draft,
      tokens: draftTokens, // Pre-computed for performance
    }])
    setDraft('')
  }

  return (
    <div>
      <ConversationView messages={messages} />

      <textarea
        value={draft}
        onChange={(e) => setDraft(e.target.value)}
        placeholder="Type your message..."
      />

      <div className="send-controls">
        <p>
          Draft: {draftTokens} tokens
          {!canSend && (
            <span className="error"> (would exceed budget)</span>
          )}
        </p>
        <button disabled={!canSend} onClick={handleSend}>
          Send Message
        </button>
      </div>

      <div className="budget-info">
        <p>
          {usage.current.toLocaleString()} / {usage.effectiveMax.toLocaleString()} tokens used
        </p>
        <p>
          {usage.available.toLocaleString()} tokens remaining
        </p>
      </div>
    </div>
  )
}
```

## Performance Considerations

### Debouncing

The hook automatically debounces token counting (default: 300ms) to prevent excessive calculations:

- Token counting happens 300ms after the last message update
- Avoids blocking the UI during rapid message additions
- Configurable via `debounceMs` option

```tsx
// Longer debounce for heavy conversations
useTokenBudgetMonitor({
  maxInputTokens: 128000,
  debounceMs: 500, // Wait 500ms
})

// Immediate counting (no debounce)
useTokenBudgetMonitor({
  maxInputTokens: 128000,
  debounceMs: 0, // Count immediately
})
```

### Async Operations

The hook uses `AbortController` to cancel in-flight calculations:

- When `updateMessages` is called while calculating, the previous calculation is aborted
- Prevents race conditions and stale state
- Ensures the UI always shows the latest calculation

### Accurate vs Fast Tokenization

Choose between speed and accuracy:

```tsx
// Fast (default): Uses estimation
useTokenBudgetMonitor({
  maxInputTokens: 128000,
  useAccurateTokenization: false, // ~10-50ms per message
})

// Accurate: Uses real tokenizer
useTokenBudgetMonitor({
  maxInputTokens: 128000,
  useAccurateTokenization: true, // ~50-200ms per message
  model: 'gpt-4o', // Required for accurate counting
})
```

### Pre-Computing Token Counts

For best performance, pre-compute token counts:

```tsx
const { calculateTokens, updateMessages } = useTokenBudgetMonitor(config)

// Pre-compute when adding message
const newMessage = {
  role: 'user',
  content: userInput,
  tokens: await calculateTokens(userInput), // Cache token count
}

setMessages(prev => [...prev, newMessage])
```

### Memory Usage

The hook maintains minimal state:

- Stores current messages reference (~1KB per conversation)
- Caches last trim result (~1-2KB)
- No persistent token count cache (use message.tokens for that)
- Automatic cleanup on unmount

## Troubleshooting

### Status not updating

Make sure you're calling `updateMessages` when messages change:

```tsx
// ❌ Wrong - not updating monitor
setMessages(newMessages)

// ✅ Correct - update monitor too
useEffect(() => {
  updateMessages(messages)
}, [messages])
```

### Thresholds not triggering

Verify thresholds are between 0 and 1 (decimal, not percentage):

```tsx
// ❌ Wrong
warningThreshold: 80  // Should be 0.8

// ✅ Correct
warningThreshold: 0.8 // 80%
```

### Auto-trim not working

Enable `autoTrim` and ensure messages are trimmable:

```tsx
// ❌ Wrong - all messages protected
{ role: 'user', content: '...', trimmable: false }

// ✅ Correct - allow trimming
{ role: 'user', content: '...' } // trimmable defaults to true
```

### Callbacks firing multiple times

Callbacks only fire when crossing thresholds, not on every update:

```tsx
// Callbacks fire when:
// - Status changes from 'safe' to 'warning'
// - Status changes from 'warning' to 'critical'
// - Status changes to 'exceeded'

// They do NOT fire when:
// - Status stays the same (e.g., 82% → 85%, both 'warning')
```

### Wrong token counts

Use the correct model name for accurate counts:

```tsx
// For accurate tokenization
useTokenBudgetMonitor({
  model: 'gpt-4o', // Must match actual model
  useAccurateTokenization: true,
})

// Or use the preset
createModelBudgetMonitor('gpt-4o')
```

### Performance issues

Increase debounce or use pre-computed token counts:

```tsx
// Longer debounce
useTokenBudgetMonitor({
  debounceMs: 500, // Wait longer before counting
})

// Pre-compute tokens
const message = {
  role: 'user',
  content: text,
  tokens: await calculateTokens(text), // Cache count
}
```
