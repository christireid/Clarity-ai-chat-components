# useTieredCache

Multi-level intelligent caching for LLM responses. Combines memory, disk, and provider-native caching with 3-tier lookup strategy for maximum hit rate and cost savings.

## Overview

`useTieredCache` provides a React interface to a sophisticated 3-tier caching system that dramatically reduces API costs and latency. It orchestrates exact, smart, and semantic caching layers to maximize cache hits while maintaining response quality.

**When to use:**
- High-volume LLM applications with repeated queries
- Chat applications with common questions
- Applications where sub-50ms response time matters
- Cost-sensitive applications (90%+ cost reduction possible)
- Systems with parameterized queries (e.g., "weather in {city}")
- Multi-user applications with overlapping queries

**When not to use:**
- Completely unique queries every time
- Applications requiring real-time data
- If you only need simple memoization → use `useMemo`
- If you need budget tracking → use `useTokenBudgetMonitor`
- If response freshness is critical (use shorter TTL)

## Basic Usage

```tsx
import { useTieredCache } from '@clarity-chat/token-optimization/react'

function ChatComponent() {
  const [prompt, setPrompt] = useState('')
  const [response, setResponse] = useState('')

  const cache = useTieredCache({
    exact: { maxSize: 1000, ttl: 3600000 },      // 1hr
    smart: { maxSize: 500, ttl: 3600000 },       // 1hr
    semantic: {
      maxSize: 200,
      maxAge: 3600000,
      similarityThreshold: 0.92,
      enableEmbeddingCache: true,
      enableContextAwareness: true,
      enablePredictiveCaching: false,
      compressionThreshold: 1000,
    },
  })

  const handleSubmit = async () => {
    // Check cache first
    const cached = await cache.get(prompt)

    if (cached.hit) {
      setResponse(cached.data!)
      console.log(`Cache hit from ${cached.tier} tier in ${cached.latency}ms`)
      return
    }

    // Fetch from API
    const apiResponse = await callLLM(prompt)

    // Cache for future requests
    await cache.set(prompt, apiResponse)
    setResponse(apiResponse)
  }

  return (
    <div>
      <textarea
        value={prompt}
        onChange={(e) => setPrompt(e.target.value)}
        placeholder="Enter your prompt..."
      />
      <button onClick={handleSubmit}>Submit</button>
      {response && <div>{response}</div>}
    </div>
  )
}
```

## API Reference

### Parameters

```tsx
useTieredCache(
  config: UseTieredCacheConfig
): UseTieredCacheReturn
```

#### `config: UseTieredCacheConfig`

| Option | Type | Required | Description |
|--------|------|----------|-------------|
| `exact` | `ExactCacheConfig` | Yes | Tier 1: O(1) hash lookup for identical queries |
| `smart` | `SmartCacheConfig` | Yes | Tier 2: Pattern matching for parameterized queries |
| `semantic` | `SemanticCacheConfig` | Yes | Tier 3: Embedding similarity for paraphrased queries |
| `trackStats` | `boolean` | No | Enable reactive stats tracking (triggers re-renders) |

#### `exact: ExactCacheConfig`

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `maxSize` | `number` | Required | Maximum number of cached entries |
| `ttl` | `number` | Required | Time-to-live in milliseconds |

#### `smart: SmartCacheConfig`

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `maxSize` | `number` | Required | Maximum number of patterns to store |
| `ttl` | `number` | Required | Time-to-live in milliseconds |

#### `semantic: SemanticCacheConfig`

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `maxSize` | `number` | Required | Maximum number of cached entries |
| `maxAge` | `number` | Required | Maximum age in milliseconds |
| `similarityThreshold` | `number` | Required | Minimum similarity score (0.7-0.95 recommended) |
| `enableEmbeddingCache` | `boolean` | Required | Cache embeddings for faster lookups |
| `enableContextAwareness` | `boolean` | Required | Use context for better matching |
| `enablePredictiveCaching` | `boolean` | Required | Preload likely-needed entries |
| `embeddingModel` | `string` | Optional | Model for generating embeddings |
| `compressionThreshold` | `number` | Required | Compress entries larger than this size (bytes) |

### Return Value

```tsx
{
  // Core cache operations
  get: (prompt: string, context?: CacheContext) => Promise<TieredCacheResult>
  set: (prompt: string, response: string, metadata?: Record<string, unknown>) => Promise<void>
  invalidate: (prompt: string) => Promise<void>
  prefetch: (items: PrefetchItem[]) => Promise<void>
  clear: () => void

  // Statistics
  getStats: () => CacheStats
  stats: CacheStats | null              // Only available when trackStats=true

  // Status
  isReady: boolean

  // React 19 features
  isPending: boolean                     // Transition in progress
  optimisticEntries: OptimisticEntry[]   // Pending cache entries
  optimisticSet: (prompt: string, response: string, metadata?: Record<string, unknown>) => void
}
```

#### `TieredCacheResult`

```tsx
{
  hit: boolean                  // Whether any tier had a cache hit
  tier?: 'exact' | 'smart' | 'semantic'  // Which tier provided the hit
  data?: string                 // The cached response data
  similarity?: number           // Similarity score (for semantic hits, 0-1)
  latency?: number             // Lookup latency in milliseconds
}
```

#### `CacheStats`

```tsx
{
  hitRate: number              // Overall cache hit rate (0-1)
  totalHits: number            // Total hits across all tiers
  totalMisses: number          // Total misses (no hit in any tier)
  exactSize: number            // Current size of exact cache
  smartSize: number            // Current size of smart cache
  semanticSize: number         // Current size of semantic cache
  tierStats: {
    exact: { hits: number, misses: number, size: number }
    smart: { hits: number, misses: number, size: number }
    semantic: { hits: number, misses: number, size: number }
  }
}
```

### With Provider-Native Caching

```tsx
import { useTieredCache } from '@clarity-chat/token-optimization/react'

function ProviderCachedChat() {
  const cache = useTieredCache({
    exact: { maxSize: 1000, ttl: 3600000 },
    smart: { maxSize: 500, ttl: 3600000 },
    semantic: {
      maxSize: 200,
      maxAge: 3600000,
      similarityThreshold: 0.92,
      enableEmbeddingCache: true,
      enableContextAwareness: false,
      enablePredictiveCaching: false,
      compressionThreshold: 1000,
    },
  })

  const callWithProviderCache = async (prompt: string) => {
    // Check local cache first (fastest)
    const cached = await cache.get(prompt)
    if (cached.hit) {
      return {
        response: cached.data,
        source: 'local-cache',
        tier: cached.tier,
        latency: cached.latency,
      }
    }

    // Call LLM with provider-native caching headers
    // Anthropic, OpenAI, and Gemini support this
    const response = await fetch('https://api.openai.com/v1/chat/completions', {
      method: 'POST',
      headers: {
        'Authorization': `Bearer ${API_KEY}`,
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({
        model: 'gpt-4o',
        messages: [{ role: 'user', content: prompt }],
        // Provider caching (reduces cost by 50-90% on repeated content)
        cache_control: { type: 'ephemeral' },
      }),
    })

    const data = await response.json()
    const result = data.choices[0].message.content

    // Store in local cache for even faster subsequent access
    await cache.set(prompt, result, {
      provider: 'openai',
      cacheType: 'provider-native',
    })

    return {
      response: result,
      source: 'api',
      cacheUsed: data.usage?.cache_read_tokens > 0,
    }
  }

  return <ChatInterface onQuery={callWithProviderCache} />
}
```

### Cache Tier Latencies

The 3-tier architecture provides optimal performance:

| Tier | Latency | Use Case | Hit Rate |
|------|---------|----------|----------|
| Exact | < 1ms | Identical queries | 30-50% |
| Smart | < 5ms | Parameterized queries | 20-30% |
| Semantic | < 50ms | Paraphrased queries | 10-20% |

**Combined hit rate: 60-100%** depending on query patterns

### Memory Usage

```
Exact Cache:    ~500 bytes per entry × maxSize
Smart Cache:    ~800 bytes per pattern × maxSize
Semantic Cache: ~2KB per entry × maxSize (includes embeddings)

Total for default config (1000/500/200):
= (1000 × 500) + (500 × 800) + (200 × 2000)
≈ 1.3 MB
```

### LRU Eviction

All tiers use LRU (Least Recently Used) eviction:

- ✅ Least accessed entries are evicted first
- ✅ Access updates entry position
- ✅ Automatic cleanup when maxSize reached
- ✅ No manual management needed

## How the Tiers Work

### Tier 1: Exact Cache

Fast O(1) hash-based lookup for identical queries:

```tsx
// Stores: Hash(prompt) → response
await cache.set('What is 2+2?', '4')

// Exact match = instant hit (< 1ms)
await cache.get('What is 2+2?')
// { hit: true, tier: 'exact', data: '4', latency: 0.3 }
```

### Tier 2: Smart Cache

Pattern extraction for parameterized queries:

```tsx
// Stores pattern: "What is the weather in {location}?"
await cache.set('What is the weather in Paris?', 'Sunny, 22°C')

// Different parameter = smart hit (< 5ms)
await cache.get('What is the weather in London?')
// { hit: true, tier: 'smart', data: 'Sunny, 22°C', latency: 2.1 }
```

Recognizes entities:
- Locations: Paris, London, Tokyo, etc.
- Dates: tomorrow, next week, 2024-01-15
- Numbers: 100, 1.5, $50
- Names: John, Alice, etc.

### Tier 3: Semantic Cache

Embedding similarity for paraphrased queries:

```tsx
await cache.set('What is the capital of France?', 'Paris')

// Paraphrased = semantic hit (< 50ms)
await cache.get('Tell me France\'s capital city')
// { hit: true, tier: 'semantic', data: 'Paris', similarity: 0.94, latency: 23.5 }
```

Uses cosine similarity on embeddings:
- Threshold: 0.92 (configurable 0.7-0.95)
- Higher = more strict matching
- Lower = more false positives

## Troubleshooting

### Low hit rate

Check your cache sizes and TTL:

```tsx
// ❌ Too small
exact: { maxSize: 10, ttl: 1000 }

// ✅ Appropriate sizing
exact: { maxSize: 1000, ttl: 3600000 }
```

Check your similarity threshold:

```tsx
// ❌ Too strict (fewer semantic hits)
similarityThreshold: 0.98

// ✅ Balanced (good hit rate)
similarityThreshold: 0.92

// ⚠️ Too loose (false positives)
similarityThreshold: 0.75
```

### Memory issues

Reduce cache sizes:

```tsx
// For memory-constrained environments
{
  exact: { maxSize: 100, ttl: 1800000 },
  smart: { maxSize: 50, ttl: 1800000 },
  semantic: {
    maxSize: 20,  // Embeddings use most memory
    maxAge: 1800000,
    similarityThreshold: 0.92,
    enableEmbeddingCache: false,  // Disable embedding cache
    enableContextAwareness: false,
    enablePredictiveCaching: false,
    compressionThreshold: 500,
  },
}
```

### Stale data

Use shorter TTL and cache invalidation:

```tsx
const cache = useTieredCache({
  exact: { maxSize: 1000, ttl: 300000 },  // 5 min instead of 1 hour
  // ...
})

// Invalidate when data updates
useEffect(() => {
  cache.invalidate('specific-prompt')
}, [dataChanged])
```

### TypeScript errors

Ensure all required fields are provided:

```tsx
// ❌ Missing required fields
semantic: { maxSize: 200 }

// ✅ All required fields
semantic: {

  similarityThreshold: 0.92,
  enableEmbeddingCache: true,
```

### Cache not working

Verify hook is outside conditional:

```tsx
// ❌ Wrong - hook in conditional
if (enabled) {
  const cache = useTieredCache(config)
}

// ✅ Correct - hook at top level
const cache = useTieredCache(config)
if (enabled) {
  // use cache
}
```
