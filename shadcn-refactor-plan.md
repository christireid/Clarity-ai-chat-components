# shadcn/ui Refactor Plan

## Snapshot
- **Current shadcn/ui version**: Not installed. The repo ships bespoke primitives in `packages/primitives` that mimic the 2023 shadcn patterns (Radix + Tailwind + cva) but diverge significantly (custom Dialog, Drawer, Dropdown, Tooltip, Toast, etc.)
- **Where it is "used" today**: Every UI surface (packages, apps, docs, storybook, tests) imports from `@clarity-chat/primitives` rather than the upstream `@/components/ui/*` files generated by the shadcn CLI. No `components.json` or CLI scripts exist in the workspace.
- **Custom UI areas to replace**: Buttons, Inputs/Textareas, Cards, Feedback badges, Avatar, Checkbox, overlay primitives (Dialog, Drawer/Sheet, Dropdown Menu, Popover, Tooltip), ScrollArea, Error state components, ripple hooks, and higher-level surfaces (Command Palette, Toasts, Context Menu, Skeleton, Progress) implemented inside `packages/react`.

## Tooling & Commands (Step 0)
- **Package manager**: `pnpm` (root `pnpm-lock.yaml`, `packageManager: pnpm@10.21.0`)
- **Install**: `pnpm install`
- **Lint**: `pnpm lint` (proxy to `npx turbo run lint`)

- **Build**: `pnpm build` (Turbo orchestration)
- Other useful scripts: `pnpm typecheck`, `pnpm storybook`, `pnpm docs`

## Current shadcn/ui Usage Audit (Step 1)

### Dependencies & config surface
- Root `package.json` + workspace packages depend on `class-variance-authority`, `clsx`, `tailwind-merge`, `lucide-react`, `framer-motion`, and a few `@radix-ui/*` helpers (`@radix-ui/react-slot`, `@radix-ui/react-checkbox`). There is **no** `components.json`, `shadcn.config.ts`, or CLI hook.
- Tailwind runs from `tailwind.config.js`, themed via CSS variables identical to the default shadcn tokens.
- No package references `shadcn` in dependencies, scripts, or docs beyond marketing copy.

### Custom primitive layer (`packages/primitives`)
| Component | File(s) | Notes |
| --- | --- | --- |
| Button & Button icons | `components/button.tsx`, `button-state-icons.tsx`, ripple hook `hooks/use-ripple-effect.ts` | Adds ripple, success/error states, custom animations beyond shadcn Button. Uses Radix Slot but not the shadcn CLI.
| Form inputs | `components/input.tsx`, `textarea.tsx`, `error-message.tsx` | Styled wrappers with focus states + inline validation message component.
| Feedback badges | `components/badge.tsx` | Adds status/soft variants.

| Checkbox | `components/checkbox.tsx` | Wraps `@radix-ui/react-checkbox` but re-implements styling and animation manually.
| Overlays | `components/dialog.tsx`, `drawer.tsx`, `dropdown-menu.tsx`, `popover.tsx`, `tooltip.tsx` | Fully homegrown portal/focus-trap logic using `framer-motion` instead of Radix primitives.
| ScrollArea | `components/scroll-area.tsx` | Custom scrollbars vs Radix ScrollArea.
| Hooks/utilities | `hooks/use-body-scroll-lock.ts`, `lib/utils.ts` | Equivalent to shadcn `useLockBodyScroll` + `cn` helper.

Exports in `packages/primitives/src/index.ts` surface all of the above; everything else in the repo imports from here (`@clarity-chat/react`, Storybook, docs, examples, integration tests).

### Higher-level custom UI overlapping shadcn patterns (`packages/react/src/components`)
- `command-palette.tsx`: bespoke command menu with grouped commands + keyboard nav (shadcn recommends `Command` built on `cmdk`).
- `context-menu.tsx`, `dropdown` usages embedded in other components.
- `toast.tsx`: homegrown provider + animation vs shadcn Sonner integration.
- `skeleton.tsx`, `progress.tsx`, `copy-button.tsx`, `context-card.tsx`, etc. all compose the custom primitives instead of native shadcn exports.

### Usage footprint
- `apps/storybook`, `apps/docs`, and every example app import UI from `@clarity-chat/primitives`.
- Test suites (`tests/integration`, `packages/react` stories) alias `@clarity-chat/primitives` to the source folder via Vite/Tsup configs, so changing primitives cascades everywhere.

**Next steps**: research the latest official shadcn/ui release, list new components vs ours, then map an incremental replacement plan.

## shadcn/ui Research (Step 2)

### Latest release snapshot
- **CLI/dist-tag**: `shadcn@3.5.1` (published 2025-11-27 per `https://registry.npmjs.org/shadcn`). This is the stable target and introduces CLI 3.x features such as namespaced registries and MCP support.
- **October 2025 component drop** (`apps/v4/content/docs/(root)/changelog.mdx`): adds Spinner, Kbd, Button Group, Input Group, Field, Item, and Empty primitives plus Button+Sheet tweaks.
- **Monorepo workflow** (`apps/v4/content/docs/(root)/monorepo.mdx`): CLI now installs components into shared `packages/ui` when run inside an app workspace; every workspace must expose a `components.json` with consistent `style`, `iconLibrary`, `baseColor`, alias paths, and (for Tailwind v4) empty `tailwind.config`.
- **Theming guidance** (`apps/v4/content/docs/(root)/theming.mdx`, `components-json.mdx`): `components.json` now drives style selection (`default` vs `new-york`), CSS-variable vs utility-class theming, base color tokens, and `rsc` opt-in/out.

### Official component inventory vs Clarity primitives
Pulled from `apps/v4/public/r/index.json`. Items in **bold** are missing or diverge heavily in this repo today.

- Foundations already mirrored here: Button, Badge, Card, Input, Textarea, Checkbox, Dialog, Drawer (Sheet analogue), Dropdown Menu, Popover, Scroll Area, Tooltip, Avatar, Progress, Skeleton, Toast (custom), Command Palette (custom), Context Menu (custom), Drawer/Sheet (custom), ScrollArea (custom), Tooltip (custom).
- **Components we currently lack or only approximate ad-hoc**: Accordion, Alert / Alert Dialog, Aspect Ratio, Breadcrumb, Button Group, Calendar, Carousel, Chart, Collapsible, **Command (cmdk-based implementation), Context Menu (radix version), Drawer (Vaul-based), Empty state, Field primitives, Hover Card, Input Group, Input OTP, Item, Kbd, Label, Menubar, Navigation Menu, Pagination, Radio Group, Resizable panels, **Select**, Separator, **Sheet (Radix Dialog-based)**, Sidebar system, Slider, **Sonner toaster integration**, Spinner, Switch, Table, Tabs, Toggle & Toggle Group, `use-mobile` helper, registry-provided hooks (e.g., `use-toast.ts`).
- Several new primitives (Field, Item, Empty, Spinner, InputGroup, ButtonGroup, Kbd) are not represented anywhere in `@clarity-chat/primitives` but show up repeatedly in the official changelog and registry.

### Migration + usage notes relevant here
1. **components.json is mandatory per workspace**: 
   - Root monorepo should host at least one for `packages/primitives` (future `@clarity-chat/ui` analog) and one for each app consuming components. 
   - Aliases must point to actual source folders (`@clarity-chat/primitives/src/components` etc.) so the CLI can drop files in the right place without manual patching.
2. **Tailwind v4 & CSS variables**:
   - For workspaces already using CSS variables (our tokens match shadcn defaults), set `tailwind.cssVariables: true`, `baseColor: "slate"` (or our palette), and leave `tailwind.config` blank when using the v4 preset (per docs).
3. **React Server Components toggle**: If any package cannot run RSC (e.g., Vite libraries), set `"rsc": false` so CLI adds `use client` automatically.
4. **Sheet API changes**: Official Sheet uses `side` prop (not `position`) and removes `size`; width/height controlled via classes—worth planning before migrating our Drawer/Sheet combo.
5. **Registry index & namespaces**: CLI 3.x allows `npx shadcn add @namespace/component`, so once `components.json` exists we can pull vetted third-party blocks (e.g., `@ai-elements/prompt-input`) to replace bespoke experiences like our prompt builders.
6. **Monorepo command usage**: Always run `npx shadcn@latest add ...` from the target workspace (e.g., `apps/storybook` vs `packages/primitives`). CLI will materialize files inside `packages/primitives` when the alias map says `@/components` → `packages/primitives/src/components`.
7. **Upcoming diff tooling**: Until the official `diff` command ships, plan to treat upstream updates as manual copy/paste; document local deviations so future upgrades are traceable.

**Actionable takeaway**: target `shadcn@3.5.1`, bootstrap `components.json` for `packages/primitives` (as the canonical UI package) plus downstream apps, then incrementally replace custom primitives with official registry files, layering our brand variants on top.
